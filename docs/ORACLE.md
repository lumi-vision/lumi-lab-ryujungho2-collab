# 오라클 (규칙 기반 합성기)

> 코드: `src/lumi_synth/oracle.py` · 실행: `scripts/make_oracle_dataset.py` · 결과: `checks/oracle/128x72_24fps.md` · 768×432 결과: `checks/oracle/768x432_24fps.md`

> 적색·줄무늬 생성기도 `oracle.py` 에 있습니다(`render_red`, `red_pair`, `render_stripes`). 이 문서는 휘도 깜빡임 오라클을 설명하며, 적색·줄무늬 기준은 [STANDARDS.md](STANDARDS.md) 에 있습니다. 아래 라벨은 `measure.analyze` 로 붙였고 2026-11-13 판정기 수정([STANDARDS.md](STANDARDS.md) §8) 이전 판정이므로 다시 판정해야 합니다.

## 1. 역할

깨끗한 영상 Y 에 **원하는 조건 그대로** 깜빡임을 넣고, 넣은 위치(마스크)·시간·판정 결과를 정답으로 함께 저장한다. 정답이 '직접 넣었으니 확실한' 데이터라서, 데이터셋의 기준점이자 GAN 결과를 평가하는 비교 대상이 된다.

## 2. 물리 모델: 선형 빛 더하기

```
X_lin[t,p] = min(1, Y_lin[t,p] + M[p] · w(t) · δ),   δ = ΔL / 200
```

- **휘도를 정확히 조절**: 선형 RGB 세 채널에 같은 δ 를 더하면 상대 휘도(가중치 합 1)가 정확히 δ 만큼 오른다. 판정 규칙의 '밝기 변화 ≥ 20 cd/m²' 조건을 cd/m² 단위로 직접 정할 수 있다(`test_oracle_additive_light_sets_luminance_exactly`: 40 cd/m² 목표 → 오차 1 cd/m² 이내).
- **물리적으로 그럴듯함**: 번쩍이는 조명, 섬광, 폭발은 빛이 더해지는 현상이다.
- **장면 보존**: 곱하거나 덮어씌우지 않으므로 바탕의 윤곽선이 남는다.
- **국소성**: 마스크 밖은 원본과 비트 단위로 같다(`test_oracle_mask_area_and_locality`).
- **한계**: 바탕이 밝으면 min(1, ·) 에서 잘려 ΔL 이 줄고, 어두운 쪽이 160 cd/m² 이상인 픽셀은 규칙상 전이가 아니다. → 의도와 판정이 어긋나는 주원인(§4).

## 3. 설계 의도 4종 (경계 쌍)

pse-test-media 의 f/a/c/l 설계처럼 **조건 하나만 일부러 무너뜨린다.** 같은 바탕에 4종을 모두 만들어 '조건 하나만 다른 쌍'이 생긴다.

| 의도 | 면적 | 주파수 | ΔL | 무너뜨린 조건 |
|---|---|---|---|---|
| hazard | 0.32~0.70 (모양이 '화면 전체'면 1.0) | 4~8 Hz | 35~80 cd/m² | 없음 |
| safe_area | **0.08~0.20** | 4~8 Hz | 35~80 | 면적 |
| safe_count | 0.32~0.70 | **1~2.5 Hz** | 35~80 | 횟수 |
| safe_lum | 0.32~0.70 | 4~8 Hz | **6~14** | 밝기 |

범위를 경계(0.25, 3 Hz, 20 cd/m²)에서 **충분히 떨어지게** 잡은 이유: 마스크 면적의 픽셀 양자화(128×72 에서 최대 오차 2.2%), 24 fps 의 시간 양자화, 8비트 밝기 양자화(약 1 cd/m²) 때문에 경계 바로 옆은 의도대로 만들 수 없다. 경계에 바짝 붙은 사례는 GAN 의 '문턱 근처 안전' 목표가 맡는다.

모양: 타원 40%, 직사각형 30%, 원 3개(여러 광원) 20%, 화면 전체 10%. 면적은 그린 뒤 **실제 픽셀 수**로 이분 탐색해 맞춘다.
파형: 사각·사인·삼각, 위상 무작위.

## 4. 정답은 의도가 아니라 판정

샘플의 라벨 = `measure.analyze` 의 결과. 의도와 판정이 다르면 `intent_ok=False` 와 무너진 조건을 manifest 에 기록하고, **버리지 않는다**(판정 결과대로 라벨). 의도-판정 일치율이 오라클의 신뢰도이며 `checks/oracle/128x72_24fps.md` 에 분할별로 적는다.

2026-11-09 기록 (실측):

- **1차 빌드: 349/352 일치.** 불일치 대부분이 hazard 의 면적 미달이었는데, 원인은 `blobs` 모양의 버그였다(원 중심이 크기와 함께 움직여 목표 0.466 에 실제 0.106). 그 밖에 safe_area 1개가 위험으로 판정됐다(바탕 움직임과 넣은 깜빡임이 같은 순간 같은 방향으로 겹친 것으로 추정 — 1차 빌드 데이터에서만 관찰, 원인 미확정).
- **버그 수정 후 재빌드: 351/352 일치.** 남은 1개(train/hazard)는 판정표의 세 조건(밝기·픽셀 횟수·면적)을 **각각은** 넘지만, 화면 기준으로 **동시에** 만족하는 1초 구간이 없어 안전으로 판정됐다.

의도와 판정이 어긋날 수 있다는 것(그리고 그 원인이 구현 버그일 수도, 바탕과의 상호작용일 수도 있다는 것)이 '라벨을 의도로 붙이면 안 되는' 근거다.

## 5. 저장 형식

`data/oracle_<트랙>/<split>/<id>.npz` (무손실, 영상 파일로 만들지 않음 — 위험 자극을 실수로 재생하지 않도록)

| 배열 | 뜻 |
|---|---|
| clean | 바탕 Y (T,H,W,3) uint8 BGR |
| flicker | 합성 X |
| mask_allow | 빛을 더하도록 허용한 영역 M |
| mask_changed | 실제로 값이 바뀐 픽셀 |
| w | 시간 파형 |
| hazard_frames, hazard_mask | 판정 규칙의 '언제·어디' 정답 |

`manifest.jsonl`: 출처·시작 프레임·분할·합성 조건(재현용)·판정 결과·의도 일치 여부·실패 원인.
