## 지표 정의 (요약)

- `roi_l1`: ROI 안 |G − Oracle|. `roi_l1_clean`은 아무것도 안 했을 때의 값(기준선)
- `diversity`: 같은 조건에서 잡음만 바꾼 출력의 ROI 픽셀 표준편차
- **세기 역산 `k`**: 휘도·적색 Oracle은 `out − clean = k · act[t] · (target − clean)` 꼴이므로 최소제곱으로 `k`를 구한다. Oracle 클립에서 역산한 `k`와 manifest의 실제 `intensity` 차이는 최대 0.0004(8비트 양자화)로 지표가 유효함을 확인했다.
  - 세기(0.15~0.85 균등)는 G의 조건 입력에 없다. 따라서 이상적인 G는 잡음으로 세기를 고르게 뽑아야 하고, 그때 `k_within_std` ≈ `k_oracle_std` ≈ 0.20이다. `k_within_std` ≈ 0이면 잡음을 무시하는 붕괴다.

## 해석

1. **모드 붕괴:** 세 설정 모두 `k_within_std`가 0.004 이하다. 같은 조건에서 잡음을 바꿔도 세기가 달라지지 않는다. λ=20·2의 `k_abs_err`(0.18~0.19)는 균등분포를 상수 하나로 맞힐 때의 이론 오차(≈0.175)와 같다. 즉 G는 **Oracle 평균판**이다.
2. **λ=0도 해결이 아니다:** 픽셀 다양성은 약 6배 늘지만 세기는 여전히 고정이다. 다양성은 ROI 전체에 일관된 변형이 아니라 국소 잡음 질감이다.
3. **패턴 미학습:** 세 설정 모두 `roi_l1` ≥ `roi_l1_clean`. 아무것도 안 하는 것보다 낫지 않다.
4. **추정 원인(구조):** G는 3×3×3 합성곱 4층(stride 1)이라 수용 영역이 9×9×9 복셀이다. ROI는 반지름 최대 약 40px이다. 잡음은 복셀마다 독립이다. 따라서 G는 ROI 전체에 같은 세기·같은 줄무늬 방향을 정할 수 없다. 손실 가중치를 바꿔도 이 제약은 남는다.
5. **Barbu와의 관계 (2026-11-07 정정):** 처음에는 저널 본문만 보고 "Barbu G는 Oracle 재구성 없이 학습했다"고 적었으나 틀렸다. 구현자 학위논문 §4.2.8에 따르면 Barbu의 Forward cGAN도 Oracle 결과를 목표로 학습했고, 저자는 "매우 결정적"이었다고 보고했다([BARBU_GAN_DEEP_DIVE.md](BARBU_GAN_DEEP_DIVE.md) 6A.3). **E1의 붕괴는 Barbu 구현에서도 관찰된 현상을 정량으로 재현한 것이다.** Barbu는 이를 해결하지 않았으므로 따라 할 해법도 없다. 이 G로 만든 데이터는 H1 시험에 불리하다.

## E2 — 판정 규칙을 학습 신호로 쓰는 G v2 (2026-11-08)

### 설계 (E1 문제에 대한 대응)

| E1 문제 | E2 대응 |
|---|---|
| Oracle 결과를 정답으로 흉내 내 결정적 | Oracle 재구성 손실 없음. **미분 가능 판정기**(`lumi.judge.soft_transition_count`)가 목표에 맞추게 함 |
| 수용 영역 9×9×9, 복셀 단위 잡음 | 3D U-Net(공간 1/4) + 시간 팽창 합성곱(1초 이상) + **클립 단위 전역 z**(FiLM) |
| 시간 파형을 조건으로 고정 | 파형을 주지 않음. 사인·코사인 시간 특징(1–12 Hz)만 주고 z가 조합 |
| D의 진짜가 Oracle | **2D 프레임 D**, 진짜 = 실제 안전 영상 프레임(공간 자연스러움만 판정, 깜빡임은 벌주지 않음) |

- 판정 규칙: `src/lumi/judge.py` — WCAG/ITU 일반 깜빡임을 픽셀 단위로(ΔY ≥ 0.1, 어두운 쪽 < 0.8, 같은 방향 전이 면적 ≥ 화면 25%, 1초 전이 > 6이면 실패). pse-test-media broadcast 40 + alternating 16 = **56/56 일치**. IRIS와 달리 국소 깜빡임을 센다.
- 목표: '문턱 넘기'(소프트 전이 ≥ 8) / '문턱 근처 통과'(2–5.5). ROI 면적 30–90%(화면 25% 기준에서 넘길 수 있는 크기).
- 배경: `scripts/prep_real_clips.py` — South 2021 안전 GIF를 128×96·24 fps·32프레임으로(학습 1,357 / 검증 204 / 시험 260, 원본 단위 분할). 저자 '위험' 163개와 판정상 이미 깜빡이는 5개 제외.
- 학습: 배치 4, 3,000스텝, Adam 2e-4, bf16, RTX 5080 약 10분. 배치 8은 16 GB를 넘겨 공유 메모리로 넘어가며 매우 느려짐.
- 평가: `scripts/eval_gan_v2.py` — 검증 204클립 × z 4개, **하드 판정기**로 측정. 같은 배경·ROI의 무작위 Oracle(휘도 혼합, 주파수·파형·위상·세기 무작위) 두 종류와 비교.

### 결과

| 지표 | E2a: RGB 잔차 | E2b: 밝기 이득·색 오프셋 + 질감 손실 | Oracle (기본 / 넓게) |
|---|---|---|---|
| '문턱 넘기' 목표 → 하드 판정 실패 | 99.0% | 98.4% | 무작위 결과 중 실패 51.8% / 50.6% |
| '문턱 근처' 목표 → 근처 통과(전이 2–6) | 99.4% | 91.4% | 무작위 결과 중 근처 12.9% / 10.2% |
| ROI 질감 보존(라플라시안 비, 넘기 / 근처) | 0.67 / 0.52 | **0.95 / 0.86** | 1.01 / 1.00 |
| z만 바꿨을 때 전이 수 표준편차(넘기 / 근처) | 2.11 / 0.54 | 0.78 / 0.51 | — |
| z만 바꿨을 때 주파수 표준편차(Hz) | 2.34 / 0.91 | 0.57 / 0.34 | — |
| 전체 주파수 표준편차(Hz) | 4.55 | 2.62 | 2.74 / 3.44 |
| 전체 밝기 진폭 표준편차 | 0.11 | 0.17 | 0.14 / 0.19 |

### 해석

1. **목표 조절:** 두 G 모두 원하는 판정 범주를 91–99%로 만든다. 문턱 근처 통과 사례는 무작위 Oracle에서 10–13%뿐이라, 같은 수를 얻으려면 Oracle은 약 7–9배를 만들어 버려야 한다.
2. **모드 붕괴 해소:** E1(같은 조건 세기 표준편차 0.0004)과 달리 z에 따라 출력이 달라진다.
3. **E2a의 문제:** ROI 질감이 절반가량 사라짐(학습 중 D가 계속 G를 구별, adv ≈ 1.2–1.6). RGB 잔차로 깜빡임을 덮어씌운 것으로 보인다.
4. **E2b의 교환:** 밝기 이득 방식(Banda 2018의 곱셈형 출력 교훈)으로 질감은 0.86–0.95까지 보존됐지만, 주파수 다양성이 줄어 Oracle 수준이 됐다. 다양성 손실이 픽셀 L1이라 G가 주파수 대신 진폭만 바꾸는 쉬운 길을 택한 것으로 보인다.
5. 학습 중 소프트 전이 수(E2b 넘기 목표 5.3)는 하드 판정(98.4% 실패)보다 낮게 나온다. 소프트 판정의 시그모이드 완화로 과소 추정되는 것이며, 평가는 하드 판정으로 한다.

### 한계

- 휘도 깜빡임만(적색·패턴 없음). 면적은 화면 비율(시야각 아님). ROI ≥ 30%만.
- 배경이 저해상도·저프레임률 GIF(반복 재생으로 32프레임 구성).
- "자연스러움"은 라플라시안 비라는 대리 지표뿐이다. 사람 평가나 실제 영상과의 분포 거리는 없다.
- 판정 라벨은 표준 문턱 판정이지 임상 위험 판정이 아니다.
