# 조건부 GAN — 규칙을 목표로, 자연스럽고 다양한 '빛'을 학습

> 코드: `src/lumi_synth/gan.py` · 학습: `scripts/train_gan.py` · 평가·데이터 저장: `scripts/eval_gan.py` · 결과: `checks/gan/README.md`
> 이전 실험 기록: 보관 브랜치 `archive/2026-11-08-before-reset` 의 `docs/GAN_EXPERIMENTS.md` (E1, E2)

## 1. 오라클과의 관계 — 왜 둘 다 필요한가

| | 오라클 | GAN |
|---|---|---|
| 물리 모델 | X_lin = Y_lin + M·w(t)·δ | X_lin = Y_lin + M·Δ_G(t,p \| Y, M, c, z) |
| 빛의 모양 | 마스크 안 **균일**, 파형은 **정해진 식** | 장면에 맞춰 **공간적으로 퍼지고**, 리듬이 **z 에 따라 다양** |
| 정답 | 판정 규칙 | 같은 판정 규칙 (학습 후 하드 판정으로 다시 잼) |
| 강점 | 조건을 정확히 통제 → 경계 쌍, 평가 기준 | 겉모습 다양성, 문턱 바로 근처 사례를 골라 만들 수 있음 |
| 약점 | 단조로움 → 탐지 모델이 '덮어씌운 티'를 외울 위험 | 규칙의 빈틈을 이용할 위험 → 하드 판정으로 반드시 재확인 |

GAN 은 **판정 기준을 새로 만들지 않는다**. 같은 규칙 아래에서 겉모습을 다양하게 만드는 역할이다. 효과는 "오라클만 vs 오라클+GAN" 으로 탐지 모델을 학습해 **합성하지 않은 실제 영상**에서 비교해야 주장할 수 있다(아직 안 함, §6).

## 2. 이전 실험에서 배운 것과 이번 설계

| 이전 결과 | 이번 대응 |
|---|---|
| **E1**: 오라클 결과를 정답(L1)으로 따라 하게 학습 → '오라클 평균판'으로 붕괴(같은 조건에서 z 를 바꿔도 세기 표준편차 0.0004). Barbu(2020) 구현에서도 같은 현상이 보고됨 | 오라클 재구성 손실 없음. **미분 가능 판정기**가 목표 판정에 맞추게 함 |
| **E2**: 판정 목표로 학습 → 목표 판정 91~99% 조절, 붕괴 해소 | 그대로 계승 |
| **E2a**: RGB 잔차 출력 → 질감 절반가량 손실 | 출력 = **빛의 양 Δ ≥ 0 한 채널, 1/4 해상도** → 원본 윤곽선이 그대로 남고 빛은 부드럽게 퍼짐 |
| **E2b**: 픽셀 L1 다양성 손실 → 주파수 대신 진폭만 다양 | 다양성 손실을 **빛의 시간 스펙트럼** 차이로 (E2c 로 계획했던 것) |

## 3. 미분 가능 판정기 (soft judge)

하드 판정의 각 단계를 시그모이드로 완화해 기울기가 흐르게 했다.

| 하드 판정 | 소프트 근사 | 차이 |
|---|---|---|
| 픽셀 전이: 직전 극값 대비 ≥ 20 cd/m² (히스테리시스) | 1~c 프레임 전 대비 변화의 큰 쪽, σ((ΔL−20)/τ) | c 프레임보다 느린 변화는 덜 센다 |
| 어두운 쪽 < 160 | σ((160 − min)/τ) | — |
| 방향별 면적 > 25% | σ((A − 0.25)/τ_a) | — |
| 상태 기계(같은 방향 연속 1번) | '직전 프레임에 같은 방향 후보가 없을 때' 새 전이 | 긴 간격을 둔 같은 방향 반복은 더 센다 |
| 두 방향 동시 후보 1번(D4) | 두 방향의 새 전이 중 큰 값만 | — (v1 에서 맞춤) |
| 1초 창 최대 | 이동 합 후 최댓값(amax, 부분 기울기) | — (v1 에서 맞춤) |

**버전 기록**: v0 은 반대 위상 깜빡임을 2번으로 세고(2 Hz 안전 영상 → 8.8, 위험 목표 충족) log-sum-exp 로 약 +0.8 과대였다. 독립 리뷰(2026-11-09)에서 발견해 v1 에서 고쳤다(`SOFT_JUDGE_VERSION`, 테스트 `test_soft_judge_counts_opposite_phase_once`). 체크포인트에 학습 때 쓴 버전을 기록한다.

남은 차이가 있으므로 **학습 후 모든 출력은 하드 판정으로 다시 잰다**. 두 판정의 일치도(상관, 위험/안전 일치율)를 `checks/gan/README.md` 에 기록한다. 단순한 화면 깜빡임에서 둘의 차이가 전이 1번 이내임을 테스트로 고정했다(`test_soft_judge_tracks_hard_judge_on_simple_flicker`).

## 4. 학습 한 스텝

```
바탕 Y (깨끗한 클립) ──┐
마스크 M (오라클 생성기, 면적 0.32~0.70, 10% 는 화면 전체) ──┤
목표 c (위험 / 문턱 근처 안전, 반반) ──┼─► G ─► 빛 Δ (1/4 해상도 → 확대) ─► X = sRGB(Y_lin + M·Δ)
잡음 z1, z2 ──────────────────────┘                                      │
                                                                         ├─► 소프트 판정 ─► 판정 손실 (위험: 전이 ≥ 8, 근처: 2~5)
                                                                         ├─► D(프레임 한 장) ─► 적대 손실 (진짜 = 깨끗한 바탕 프레임)
                                       Δ(z1), Δ(z2) 의 시간 스펙트럼 차이 ─► 다양성 손실
손실_G = 1.0·판정 + 0.1·적대 + 0.05·다양성
```

- **문턱 근처 안전 목표**(전이 2~5번 = 깜빡임 1~2.5번/초, 면적은 25% 초과): 위험과 조건 하나(횟수)만 다른 **가장 어려운 음성 사례**. 무작위 오라클로는 드물게 나오는 사례를 골라 만들 수 있다는 것이 GAN 의 실질적 이점이다(E2 에서 무작위 오라클은 10~13% 만 '근처'였다).
- **D 는 프레임 한 장만** 본다: 깜빡임 자체는 벌주지 않고, 빛 번짐이 어색한지(네모 덩어리 등)만 본다.
- **마스크 밖은 구조적으로 원본과 같다**(M 을 곱함) → 국소성 손실이 필요 없다(`test_gan_locality_and_shapes`).

## 5. 평가 (검증 분할만, 하드 판정으로)

1. 조절력: 목표 '위험' → 실제 위험 비율, 목표 '근처' → 안전이면서 1~3회/초 비율
2. 대리 판정 신뢰도: 소프트 ↔ 하드 전이 수 상관, 위험 판정 일치율
3. 다양성: 같은 (Y, M, c) 에서 z 만 바꿨을 때 깜빡임 수·주 주파수의 표준편차
4. 국소성: 마스크 밖 바뀐 값의 개수 (0)
5. 자연스러움 — **코드 지표만** (합성 결과는 광과민성 위험 자극이라 사람이 보고 평가하지 않는다)
   - 질감 보존율: 마스크 안 윤곽선 에너지(라플라시안) 출력/원본, 1 = 장면 그대로
   - 빛 공간 변이계수: 마스크 안 빛 Δ 의 std/mean, 오라클 = 0(균일)
   - 기준선: 같은 바탕·마스크에 오라클(hazard 조건)을 넣은 결과
6. 대조군: 같은 구조의 학습하지 않은 G

시험 분할(Elephants Dream)은 쓰지 않는다 — 탐지 모델 최종 평가용으로 남긴다.

`data/gan/val/` 샘플은 **평가 전용**(`purpose: evaluation_only`)이다. 탐지 모델 학습용 GAN 샘플은 train 바탕으로 따로 만들어야 한다(아직 스크립트 없음). 그렇지 않으면 val 누수로 H1 비교가 불공정해진다.

## 6. 하지 않은 것 (주장하지 않음)

- 실제 영상과의 분포 거리(예: 프레임 특징 분포 비교): 없음. 사람 평가는 위험 자극이라 하지 않는다(방침)
- 노트북 학습은 64×36, 500스텝의 **동작 확인**이다. 본 학습은 집 PC(RTX 5080)에서 128×72 이상, 수천 스텝으로 한다
- 탐지 모델을 학습해 "오라클 vs 오라클+GAN" 을 비교하는 실험(H1): 아직 안 함
- 적색 깜빡임·패턴: §1~§9 의 GAN 은 휘도 깜빡임만 다룬다. 적색·줄무늬 GAN 은 2026-11-14 에 따로 만들었다(§10). 규칙 기반 적색·줄무늬 생성기는 `oracle.py` 에 있다(아래 참고).
- 768×432 결과는 `checks/gan/u_sweep_SUMMARY.md` 와 `checks/oracle/768x432_24fps.md` 에 있다. 이 문서 §7~§9 의 수치는 64×36 노트북 실험이다.
- 판정 라벨은 `measure.analyze` 가 만들었고, 2026-11-13 판정기 버그 6건 수정([STANDARDS.md](STANDARDS.md) §8) 이전의 판정기로 붙인 것이다. 라벨을 다시 만들어야 한다.
- 적색·줄무늬 생성기: `oracle.py` 의 `render_red`, `red_pair`(적색 쌍), `render_stripes`(줄무늬). 기준과 점검은 [STANDARDS.md](STANDARDS.md), `checks/red/`, `checks/pattern/` 를 보세요.
- 만들어서 보기(2026-11-14): 플레이어의 '생성…' 이 체크포인트의 G 와 위 규칙 기반 생성기를 그 자리에서 돌린다(`src/lumi_synth/generate.py`, 사용법은 [README](../README.md) '영상 확인'). §5 의 "사람이 보고 평가하지 않는다"는 평가 방침은 그대로다 — 플레이어는 결과를 확인하는 도구이고, 지표는 여전히 코드로 잰다.
- 판정 규칙 기록(2026-11-14): `train_gan.py` 가 체크포인트 `config.judge_rule` 에 학습 때의 동시성 창(ms)과 1초 창을 적는다. 이 기록이 없는 체크포인트(`u_*`, `u2k_*`, `ufp32_*`)는 2프레임 동시성 창으로 학습한 것이다.
- 다양성 손실 진폭 정규화(2026-11-14, 실험용): `train_gan.py --div-norm`. 스펙트럼을 크기로 나눠 세기가 아니라 리듬 차이만 보게 한다(`gan.spectral_diversity(normalize=True)`). 결과가 나오면 `checks/gan/` 에 적는다.

## 7. 첫 실측 결과와 해석 (2026-11-09, 노트북 CPU, `checks/gan/README.md`)

조건: 64×36, 500스텝, 배치 4, 소프트 판정기 **v0**(리뷰 전) 로 학습. 검증 바탕 12개 × 목표 2종 × z 4개, 하드 판정으로 측정.

| 지표 | 학습한 G | 학습 안 한 G |
|---|---|---|
| 목표 '위험' → 실제 위험 | 47/48 (98%) | 10/48 (21%) |
| 목표 '근처 안전' → 안전 & 1~3회/초 | 44/48 (92%) | 23/48 (48%) |
| 소프트↔하드 전이 수 상관 / 위험 판정 일치 | 0.99 / 97% | 0.89 / 88% |
| z 만 바꿨을 때 주 주파수 표준편차 | **0.38 Hz** | 2.87 Hz |
| 마스크 밖 바뀐 값 | 0 | 0 |
| 질감 보존율 (오라클 0.949) | 0.977 | 0.947 |
| 빛 공간 변이계수 (오라클 0) | 0.557 | 0.104 |

- **조절력은 학습으로 생겼다**: 대조군 대비 위험 목표 21% → 98%, 문턱 근처 목표 48% → 92%.
- **다양성은 학습으로 줄었다 (부분 모드 붕괴)**: 같은 조건에서 z 를 바꿔도 리듬이 거의 같다. 판정 손실(가중치 1.0)이 0 근처로 빨리 내려간 뒤 다양성 손실(가중치 0.05)이 너무 약해 z 를 무시하는 쪽으로 수렴한 것으로 보인다(추정, 미검증).
- **자연스러움 지표는 해석에 주의**: G 의 질감 보존율(0.977)이 오라클(0.949)보다 높지만, G 가 더한 빛의 평균(21.8 cd/m²)이 오라클 범위(35~80)보다 작아서 생긴 차이일 수 있다(빛이 적으면 대비가 덜 눌림). 같은 빛의 양에서 비교해야 'G 가 더 자연스럽다'고 말할 수 있다. 빛 공간 변이계수 0.557 은 G 가 빛을 마스크 안에 고르지 않게 퍼뜨린다는 뜻이며, 그것이 '자연스러운 퍼짐'인지는 이 지표만으로 알 수 없다.
- 다음 실험(미실행): λ_div 를 0.05 → 0.5·1.0 으로 올려 조절력과 다양성의 교환 관계를 측정, 소프트 판정기 v1 로 다시 학습, 집 PC 에서 128×72·수천 스텝.

## 8. 두 번째 실측: 소프트 판정기 v1 + λ_div 0.5 (2026-11-09, `checks/gan/v1_div05.md`)

같은 조건(64×36, 500스텝, 배치 4, 시드 0), 같은 평가(검증 바탕 12개 × 목표 2종 × z 4개, 하드 판정).

| 지표 | v0 (λ_div 0.05) | **v1 (λ_div 0.5)** | 학습 안 한 G |
|---|---|---|---|
| 목표 '위험' → 실제 위험 | 47/48 (98%) | **48/48 (100%)** | 10/48 (21%) |
| 목표 '근처 안전' → 안전 & 1~3회/초 | 44/48 (92%) | **47/48 (98%)** | 23/48 (48%) |
| 소프트↔하드 위험 판정 일치 | 93/96 (97%) | **96/96 (100%)** | 84/96 (88%) |
| z 만 바꿨을 때 주 주파수 표준편차 | 0.38 Hz | **1.92 Hz** | 2.87 Hz |
| z 만 바꿨을 때 깜빡임 수 표준편차 | 0.42 | **0.89** | 1.00 |
| 질감 보존율 (오라클 0.949) | 0.977 | 0.975 | 0.947 |
| 빛 공간 변이계수 | 0.557 | 0.572 | 0.104 |
| 마스크 밖 바뀐 값 | 0 | 0 | 0 |

- 이 설정에서는 **조절력을 잃지 않고 다양성이 회복됐다**: z 주파수 표준편차 0.38 → 1.92 Hz (학습 안 한 G 의 2.87 에는 못 미침).
- **원인을 하나로 말할 수 없다**: v0 → v1 사이에 바꾼 것이 두 가지(소프트 판정기 v0→v1, λ_div 0.05→0.5)다. 어느 쪽의 효과인지 가르려면 하나씩만 바꾼 실험이 필요하다(미실행).
- **표본이 작다**: 시드 1개, 검증 바탕 12개(한 영화). 반복 시드와 더 많은 바탕에서 같은 경향이 나오는지 확인해야 논문 수치로 쓸 수 있다.

| z 만 바꿨을 때 깜빡임 수 std | 0.42 | **0.34** | 0.89 |
| 질감 보존율 (오라클 0.949) | 0.977 | 0.980 | 0.975 |
| 빛 공간 변이계수 | 0.557 | 0.474 | 0.572 |
| 평균 추가 빛 (cd/m²) | 21.8 | 30.9 | 24.8 |

해석 (시드 1개라 잠정):
- **다양성 회복은 λ_div 덕분이다.** 판정기만 고치면 다양성은 오히려 더 무너졌다(주파수 std 0.38 → 0.06 Hz). λ_div 를 0.5 로 올렸을 때만 1.92 Hz 로 회복됐다.
- **판정기 수정은 조절력·대리 판정 일치를 올렸다.** 근처 안전 92% → 100%, 소프트↔하드 일치 97% → 100%. 반대 위상으로 '가짜 위험'을 만드는 빈틈이 없어지면서 목표가 정확해진 것과 맞는 결과다(인과는 미검증).
- 판정기가 정확해질수록 G 는 목표를 맞추는 한 가지 리듬으로 쉽게 수렴한다 → **다양성 손실이 필수**이고, 그 가중치는 조절력과 함께 골라야 한다(λ_div 0.5 에서 근처 안전 98%, 1개 실패).

## 10. 적색·줄무늬 생성기 (2026-11-14)

> 코드: `gan.py` §3-2 (`RedGenerator`, `StripeGenerator`, `soft_judge_red`, `soft_judge_stripe`) · 학습: `train_gan.py --hazard red|stripe` · 평가: `scripts/eval_gan_hazards.py` · 결과: `checks/gan/r_*.md`, `checks/gan/s_*.md`

휘도 G 와 같은 원리를 종류별로 쓴다. 생성기는 **종류마다 따로 학습**하고(체크포인트 `config.hazard`), 신경망 몸통은 `LightGenerator` 와 같다. 다른 것은 '섞는 식'과 '판정 손실'뿐이다.

| | 휘도 (§1~§9) | 적색 | 줄무늬 |
|---|---|---|---|
| G 가 정하는 것 | 더할 빛 Δ(t,p) | 빨강으로 바꾸는 정도 ρ(t,p) ∈ [0,1] | 줄무늬가 덮는 정도 a(t,p) ∈ [0,1] + 클립별 cpd·방향·흐름 속도·밝은 줄 휘도 |
| 섞는 식 (선형 빛) | Y + M·Δ | (1 − M·ρ)·Y + M·ρ·R(Y) | (1 − M·a)·Y + M·a·S |
| 넣는 것 | 흰 빛 | R(Y) = 장면과 **같은 휘도의 순수 빨강**(선형 R = Y/0.2126, [0.10, 1] 로 자름) | S = 사인 줄무늬, 어두운 줄 10 cd/m² ↔ 밝은 줄 80~140 cd/m² |
| 판정 손실 | `soft_judge`: 휘도 전이 수 | `soft_judge_red`: 포화 빨강(R/(R+G+B) ≥ 0.8, R−G−B ≥ 0.0625)·Δu′v′ > 0.2 를 시그모이드로 → 적색 전이 수 | `soft_judge_stripe`: 명암 a·(hi − lo) 가 기준을 넘는 픽셀 면적 > 40% 인 프레임이 1초 창 안에 이어진 시간 |
| 위험 목표 | 전이 ≥ 8 | 전이 ≥ 8 | 지속 ≥ 0.7초 (기준 0.5초) |
| 근처 안전 목표 | 전이 2~5 | 전이 2~5 | 지속 ≤ 0.25초 이면서 줄무늬는 보임(최대 면적 ≥ 20%) |
| 다양성 손실 | Δ 의 시간 스펙트럼 | ρ 의 시간 스펙트럼 | 줄무늬 조건(cpd·방향·속도·밝기)의 차이 |
| 하드 판정(라벨) | `measure.analyze` | `measure.analyze_red` | `measure.analyze_pattern` (평가에서는 빠른 `stripe_freq` 쿼드트리+가버, 일부만 스캔선 대조) |

설계 선택과 한계 (모두 구현 선택 — 근거는 아래 확인 수치뿐이다)

- **적색은 휘도를 지키며 색만 바꾼다.** 그래서 어두운 장면에서는 휘도 깜빡임 없이 적색 전이만 생긴다. 밝은 픽셀(Y > 0.2126 = 42.5 cd/m²)은 순수 빨강이 그 밝기를 낼 수 없어 어두워지고, 그 면적이 25% 를 넘으면 휘도 깜빡임 위험도 함께 생긴다(확인: 평균 84 cd/m² 인 바탕에서 휘도 5회/초·면적 33%).
- **이미 붉은 장면은 적색 전이가 안 생긴다**(색 차이가 0.2 에 못 미침). 중성·초록·파랑 장면에서 Δu′v′ 약 0.26~0.32.
- **적색 소프트 판정기는 하드 판정의 '깜빡임 쌍 짓기'를 흉내 내지 않는다.** 규칙 기반 적색 깜빡임 1~8 Hz 에서 소프트 값과 하드 전이 수의 차이는 0.2 이내였다(2026-11-14).
- **줄무늬는 식으로 그린다.** G 는 조건과 덮는 정도만 정하고 줄 자체는 사인 함수다. 그래서 cpd 대역과 규칙성은 구조상 지켜진다. 대신 이 판정 손실은 **영상 픽셀을 보지 않는 대리 판정**이라, 하드 판정으로 다시 재는 것이 휘도·적색보다 더 중요하다.
- **줄무늬 첫 버전의 범위**: 직선 줄무늬만(동심원·방사형·물결 없음), 정지와 한 방향 흐름만(명암 반전 없음), cpd 1.3~7.0. 흐르는 줄무늬는 각 픽셀이 주기적으로 깜빡여 휘도 깜빡임 위험도 함께 생길 수 있다(확인: 3 cpd·4°/s 에서 휘도 12회/초·면적 27%).
- **섞는 식 확인**(ρ·a 를 직접 넣어 하드 판정, 2026-11-14): 적색 — 검증 바탕 5개에서 5 Hz 사각파 ρ 가 모두 적색 전이 10·면적 49~50% 로 위험 판정. 줄무늬 — a = 1, 1.3·3·5·7 cpd 에서 쿼드트리 면적 60~62%(영역 60%), 스캔선 판정도 위험.
- **현실성 신호는 여전히 없다.** D 의 진짜는 깨끗한 바탕 프레임이라, 빨갛게 물든 프레임과 줄무늬 프레임은 쉽게 가짜로 구별된다. 적대 손실(가중치 0.1)은 판정 손실과 반대로 당긴다.
