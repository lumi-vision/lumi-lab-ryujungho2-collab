# 팀 의견 요청: 합성 위험 영상의 '현실성'을 어떻게 올릴까 (2026-11-17)

> 자세한 수치와 경과: [GDR_VERIFY.md](GDR_VERIFY.md) · 생성기 구조: [GENERATORS.md](GENERATORS.md)
> 확인 영상(이 PC 에서만): `LUMI_영상보기.bat` → `data/playlist/review/` — ⚠️ 광과민성 위험 자극, 공유·녹화 금지

## 1. 지금 생성기(G)는 어떻게 만들고 있나

- **학습 데이터**: 판정기로 안전을 확인한 바탕 클립만 쓴다 — Big Buck Bunny(Blender 오픈 무비) 2초 클립 60개(768×432, 24 fps, 48프레임). **실제 위험 영상은 학습에 쓰지 않는다.**
- **G 가 정하는 것**: 영상을 새로 그리지 않고, 정해 둔 식에 넣을 '언제·어디에·얼마나'만 정한다 — 휘도는 더할 빛의 양, 적색은 빨강으로 바꾸는 정도, 줄무늬는 무늬가 덮는 정도. 무늬 모양(직선·방사형 등)·색·파형은 식으로 그리고 무작위로 고른다.
- **G 를 가르치는 것**
  1. 미분 가능한 판정기 — 표준 규칙(1초에 3번 초과, 면적 25%·40%, 적색 정의 등)을 부드럽게 만든 것. "위험 목표면 규칙을 넘게, 근처 안전 목표면 바로 아래로" (주된 신호)
  2. 판별기 D — 깨끗한 바탕 프레임을 '진짜'로 보고 생성 프레임이 그렇게 보이게 민다 (가중치 0.1, 약함)
  3. 다양성 손실 — 잡음 z 가 바뀌면 리듬이 달라지게
- **결과적으로 배운 것**: "규칙을 정확히 맞추거나 아슬아슬하게 피하는 시간 리듬과 공간 분포". 정답(라벨)은 생성 의도가 아니라 하드 판정기가 붙인다.

## 2. 이렇게 해봤더니 (2026-11-14 ~ 16)

| 해본 것 | 결과 |
|---|---|
| 휘도·적색·줄무늬 G 를 각각 학습 | 목표(위험 / 근처 안전) 적중 85~100%. **경계 근처 영상을 원하는 대로, 정답이 확실하게, 대량으로** 만든다 |
| G 영상으로 ROI 탐지기를 학습 → 다른 방식(규칙 생성기)으로 만든 위험 영상에서 시험 | 처음엔 적색 재현율 **0.04** — 탐지기가 위험이 아니라 'G 특유의 빨강 모양'을 배웠다 |
| G 의 다양성(색·등휘도·파형)과 탐지기 입력(휘도·색도 등 규칙의 양)을 함께 고침 | 다른 생성기에서 휘도 0.96 · 적색 0.92 · 줄무늬 0.88 재현율. 하나만 고쳤을 때는 모두 실패 |
| 휘도 깜빡임과 줄무늬를 떼어 놓은 통제 실험(하나만 바꿈, 시드 2개) | 휘도 깜빡임을 줄무늬로 잘못 잡는 일 21 → 6~11, 줄무늬 정밀도 0.31 → 0.72~0.81, 재현율 0.88 유지 |
| 탐지 → 보정(원본 복원) 전체 흐름 | 같은 안전 수준에서 전체 감광보다 원본에 가깝다(화면 전체 LPIPS 0.66 → 0.45~0.49) |
| 사람이 직접 보는 확인 묶음(정지 그림·mp4) | **판정은 맞는데 겉모습이 실제 위험 영상 같지 않다** (아래 3) |

## 3. 드러난 문제

1. **실제처럼 보이지 않는다.** 경계가 날카로운 사각형·타원 빛, 장면과 무관하게 평평한 빨강·보라, 회색 줄무늬가 덮인 모습이다. 실제 섬광(폭발·카메라 플래시·번개·무대 조명·장면 전환)이 어떻게 생겼는지 G 는 본 적이 없다.
2. **그래서 탐지기가 '합성의 흔적'을 배울 위험이 있다.** 실제로 G 가 한 가지 모양만 만들 때마다 탐지기가 그 모양에 기대는 것을 세 번 확인했다(적색 0.04, 사인파 깜빡임 놓침, 정지 줄무늬 0/7). 겉모습이 비현실적인 것도 같은 종류의 흔적일 수 있다.
3. **현실성을 재는 수치가 없다.** 지금은 "덜 자연스럽다"를 눈으로만 판단한다. 고쳐도 나아졌는지 말할 수 없다.
4. **바탕이 영화 한 편(애니메이션)뿐**이다. 실사·어두운 장면·게임·방송 화면이 없다.
5. 24 fps 라 임상적으로 중요한 15~20 Hz 깜빡임을 만들 수 없다(별도로 60 fps 트랙 필요).

## 5. 제안 (추천 순서)

1. **현실성을 먼저 잰다** (②가 '예'일 때). 실제 위험 영상과 합성 영상에서 같은 특징(깜빡임 파형, 경계 날카로움, 영역 모양·개수·면적, 색, 움직임)을 뽑아 분포를 비교하고, 둘을 구별하는 간단한 분류기를 만든다. 쉽게 구별되면 '무엇으로 구별했는지'가 고칠 방향이다.
2. **실제 영상의 빛 변화를 재료로 쓴다** (③이 '예'일 때, 추천 1순위). 안전한 실제 영상에는 기준 아래의 진짜 섬광이 많다. 그 '빛 변화 조각'(어디가·어떤 모양으로·어떻게 퍼지며 밝아지나)을 뽑아 두고, G 는 그 조각을 **언제·몇 번·얼마나 세게** 반복할지만 정한다. 모양은 실제에서, 위험 여부는 우리가 조절한다 — 지금 G 가 잘하는 '경계 맞추기'를 그대로 살린다. 실제 위험 영상은 학습에 쓰지 않아도 된다.
3. **물리적으로 그럴듯하게** — 경계를 부드럽게(광원에서 멀어질수록 약해지는 빛), 밝은 물체·광원 위치에 넣고 움직임을 따라가게, 화면 전체 노출 변화(번개·플래시), 재압축(H.264) 같은 열화.
4. **그래도 부족하면** 실제 섬광 성분과 비교하는 현실성 판별자를 학습에 넣는다(④). 실제 위험 영상이 20개 안팎이라 과적합 위험이 크다.
5. 병행: 바탕을 영화 4편 이상으로(⑤), 60 fps 트랙.

각 단계 뒤에 1의 수치와 '다른 생성기로 만든 위험 영상에서의 탐지 성능'이 좋아지는지 확인한다. 좋아지지 않으면 그 자체를 기록한다.
