# 생성(G) → ROI 탐지 → 보정: 단계별 검증 (2026-11-14 시작)

> 묻는 것: **G 가 만든 휘도·적색·줄무늬 위험 영상으로 학습하면, 위험 영역을 찾고(ROI 탐지) 자연스럽게 고칠(보정) 수 있는가.**
> 코드: `src/lumi_synth/roi.py` · `scripts/make_gdr_dataset.py` · `scripts/train_roi.py` · `scripts/eval_roi.py` · `scripts/train_corrector.py` · `scripts/eval_corrector.py` · 결과: `checks/gdr/`

이 문서의 탐지기·보정기는 **검증용 작은 모델**이다. 보정 모델의 최종 구조는 보정 담당 팀원이 정한다([PLAN.md](../PLAN.md) §0). 여기서는 "우리 데이터로 학습이 되는가"만 본다.

학습한 매개변수(체크포인트)와 그 학습 데이터·방법·결과 목록: [MODELS.md](MODELS.md) (`python scripts/model_registry.py`). 학습 스크립트는 같은 이름의 체크포인트가 있으면 멈춘다(`--overwrite` 로만 덮어씀).

## 원칙

- **정답은 생성 의도가 아니라 하드 판정기의 결과다.** 의도가 '위험'이어도 판정이 안전이면 정답은 '위험 없음'이다.
- **탐지 정답(튜브)** = 판정기가 위험하다고 한 1초 창에서 화면 전이를 만든 픽셀(휘도·적색), 위험 프레임의 줄무늬 픽셀(줄무늬). 시간×세로×가로 모양이라 '튜브'라고 부른다. G 가 바꾼 영역 전체가 아니다.
- **보정 평가는 판정기가 채점한다**: 보정 결과를 판정기에 다시 넣어 안전한지 보고, 원본과 얼마나 다른지 잰다(PLAN §4).
- 결과 영상은 보지 않는다. 지표는 모두 코드로 잰다(광과민성 위험 자극).
- 분할: 학습 = train 바탕 60개, 검증 = val 바탕 12개(다른 영화). test 바탕 16개와 South 2021 위험 163개는 쓰지 않는다(최종 시험용).
- 줄무늬 판정은 쿼드트리+가버, 초당 약 10장 표본이다(플레이어 '빠른 판정'과 같음). 기준 판정기(스캔선)는 클립당 1~4분이라 전체에 쓰지 못했다.

| (없음) | – | test 분할 16클립, South 2021 위험 163개 | 최종 시험용. 이 검증에서 쓰지 않는다 |

- 표본 id: `<분할>_<바탕 번호>_<g|r><종류>_<의도>_<반복>` (예: `train_007_gred_near_1`), 바탕 그대로는 `<분할>_<바탕 번호>_clean`.
- 표본마다 `manifest.jsonl` 에 생성원(체크포인트 이름·sha256 또는 규칙 레시피), 생성 의도, 판정 요약을 적는다.
- 강제: 학습 스크립트는 train 분할·G 표본이 아니면 멈추고, 평가 스크립트는 train 분할이 섞이면 멈춘다(`gdr_common.require_split`).
- 구분표: `python scripts/gdr_dataset_card.py --name v1` → `data/gdr/v1/DATASET.md`, `checks/gdr/dataset_v1.md` (폴더별 생성원·종류·의도·판정 결과 집계와 섞임 점검).
- 데이터 버전: `v1` = 휘도 G `w_div2.0_2k_s0` + 적색 G `r_crisp2_div2.0_s0`. `v2` = v1 의 휘도·바탕 그대로·규칙 표본(하드링크, 같은 파일) + 적색 G v3 `r3z_crisp2_div2.0_s0` 로 새로 만든 적색. 결과 파일 이름은 `checks/gdr/<버전>_<모델>_<폴더>.md`.
- 1차에 쓴 G: 휘도 `w_div2.0_2k_s0.pt`, 적색 `r_crisp2_div2.0_s0.pt`(전환 또렷함 손실 — 위험 94%·근처 안전 96%·보임 75%, `r_div2.0_s0` 은 88%·96%·60%).

## 단계와 합격 기준

합격 기준은 **결과를 보기 전에 정했다(2026-11-14).** 모두 구현 선택이며 표준에 없는 값이다. 사용자가 바꿀 수 있다.

| 단계 | 하는 일 | 합격 기준 |
|---|---|---|
| 1. G 학습·평가 | 종류별 G 를 학습(`train_gan.py`)하고, 목표대로 만드는가 (검증 바탕 12 × 목표 2 × z 4 = 96개, 하드 판정) | 목표 '위험' → 그 종류 위험 ≥ 90% · 목표 '근처 안전' → 안전 ≥ 90% · 마스크 밖 변화 0 · z 를 바꾸면 결과가 달라짐(학습 안 한 G 의 다양성의 절반 이상) |
| 2. 데이터 | G 3종으로 학습·검증 쌍을 만들고 판정기로 라벨을 붙임 | 종류마다 판정기 기준 위험 표본이 학습 60개 이상 · 마스크 밖 변화 0 · 깨끗한 바탕의 튜브는 비어 있음 |
| 3. ROI 탐지기 학습·평가 | 2단계 데이터로 탐지기를 학습(`train_roi.py`) → 검증 바탕(같은 G)과 규칙 생성기(다른 생성기)에서 판정기 튜브와 비교 | 같은 G: 종류별 클립 재현율 ≥ 0.9, 정밀도 ≥ 0.9, 튜브 IoU ≥ 0.7 · 다른 생성기: 재현율 ≥ 0.7 (G 의 흔적이 아니라 위험을 배웠는지) |
| 4. 보정기 학습·평가 | 2단계 쌍으로 **위험 영상 → 원본으로 되돌리는 보정**을 학습(`train_corrector.py`) → 보정 결과를 판정기에 다시 넣음 + 원본과 비교. 대조군 = 규칙 보정 | 보정 뒤 안전 ≥ 90% · 튜브 밖 변화 0 · 튜브 안 PSNR 이 보정 전보다 6 dB 이상 높고 규칙 보정보다 높음 · 질감 0.8~1.2 · 시간 변화 0.7~1.3 · 이음새 ≤ 1.3 · 안전한 영상을 건드린 비율 ≤ 10% |
| 5. 실제 영상 | 실제 위험 영상(Kaya 2025, 보정용 몫)에서 탐지기 대 판정기 | 기준 없음 — 수치만 보고한다. South 2021 위험 163개는 사용자가 정할 때까지 쓰지 않는다 |

지표의 뜻 (`roi.py` §4)

| 지표 | 뜻 | 좋은 값 |
|---|---|---|
| 클립 재현율·정밀도 | 종류별 '이 클립에 그 위험이 있는가'. 탐지기는 어느 프레임이든 예측 면적이 화면의 12.5% 이상이면 '있음' | 1 |
| 튜브 IoU | 판정기 튜브와 탐지기 튜브가 겹치는 정도(1/4 해상도) | 1 |
| PSNR (튜브 안) | 원본과의 차이 (dB) | 클수록 |
| 질감 | 윤곽선 에너지 출력/원본 | 1 (작으면 뭉개짐, 크면 무늬가 남음) |
| 시간 변화 | 프레임 간 변화량 출력/원본 | 1 (크면 깜빡임이 남음, 작으면 움직임이 뭉개짐) |
| 이음새 | 튜브 경계를 가로지르는 밝기 차이 출력/원본 | 1 (크면 경계가 눈에 띔) |

## 구현 차수 (2026-11-14 로드맵) 와의 대응

검증은 아래 차수 순서로 한다. 차수마다 위 1~4단계(G → 데이터 → 탐지기 학습 → 보정기 학습)를 한 번씩 돈다.

| 차수 | 로드맵 | 지금 있는 것 | 빠진 것 |
|---|---|---|---|
| 1차 | 15~20 Hz 고대비 명암 점멸, 적색 계열 점멸. 표준 기준대로 휘도·주파수·면적 측정 | 판정기 `measure.analyze`·`analyze_red`(면적 25%, 1초 3회 초과, 20 cd/m², 적색 정의) · 휘도 G · 적색 G · 규칙 생성기 | **15~20 Hz 는 지금 데이터(24 fps)로 만들 수 없다**(24 fps 가 담을 수 있는 최대는 12 Hz). 지금 G 가 만드는 범위는 초당 약 1.5~12회. 15~20 Hz 는 60 fps 바탕이 필요하다 |
| 2차 | 명암 반전·진동 줄무늬. 2D FFT 로 공간 주파수, 시간축에서 움직임·반전 | 규칙 생성기의 반전·흐름 줄무늬(`oracle.render_stripes`) · `stripe_freq`(패치 FFT + 쿼드트리 + 가버) · 스캔선 판정기의 움직임 분류(`measure.classify_motion`) | 줄무늬 G 는 정지·한 방향 흐름만(반전 없음). 빠른 줄무늬 판정(쿼드트리)은 움직임을 보지 않는다 |
| 3차 | 정적 줄무늬·체크무늬·동심원 등 반복 패턴. 시야각 기반 공간 주파수와 대비 | 정적 직선 줄무늬(G·규칙) · `stripe_freq.render_pattern` 의 동심원·방사·나선·처프·체커(탐지기 평가용) · cpd 는 시야각 기준(`measure.pixels_per_degree`) | 줄무늬 G 는 직선만. 체크무늬·물방울 격자는 쿼드트리가 줄무늬로 보지 않는다(기준 해석 문제, 미결) |
| 4차 | 점멸 + 공간 패턴이 겹치는 경우의 위험도 결합, 국소 보정 성능 평가 | 판정기는 종류별로 따로 판정하고 OR 한다 · 이 문서의 보정 평가(4단계) | 겹친 표본을 만드는 생성기 없음(흐르는 줄무늬가 휘도 위험을 함께 내는 경우만 있음). 위험도 '결합' 규칙 없음 — 표준에도 없다 |

- FFT 는 공간·시간 주파수를 재는 도구로, E-Means 는 줄무늬 후보를 묶는 보조 도구로만 쓴다(`stripe_freq.py`). 위험 판정은 표준의 수치 기준(면적·횟수·휘도·cpd·지속 시간)으로 하며, 어느 알고리즘도 단독으로 임상 위험을 판정하지 않는다.
- **사용자 결정(2026-11-14): 1차는 24 fps 로 먼저 끝낸다**(초당 3회 초과~12 Hz). 15~20 Hz 는 그 뒤 60 fps 트랙(바탕 다시 만들기, G 다시 학습)으로 추가한다.
- 그래서 **1차는 휘도·적색만으로 G → 데이터 → 탐지 → 보정을 끝까지** 돌리고, 줄무늬는 2·3차에서 따로 한다. 탐지기·보정기 구조는 세 종류를 모두 받게 만들어 두었으므로 차수가 올라가면 데이터만 더해 다시 학습한다.

## 보정·평가 의사결정 (사용자 결정 문서, 2026-11-15)

| 항목 | 채택 | 구현 |
|---|---|---|
| 영역 분리 | 합성 비중 α(Alpha) + 위험 마스크를 **따로** 둔다: M_hazard(판정기 튜브), M_loss(α ≥ 0.95) | G 가 합성할 때 α 를 계산해 `<id>.alpha.npz` 로 저장(`generate.render` → `make_gdr_dataset`). 이전 표본은 레시피로 다시 합성해 채움(`gdr_backfill_alpha.py`, 저장 영상과 최대 차이 기록) |
| α 정의 | 원본 대신 합성한 몫. 휘도(빛 더하기)는 255 포화 채널 비율, 적색은 1 − (1 − κ)(1 − ρ), 줄무늬는 덮는 정도 a, 규칙 적색·줄무늬는 영역 안 1 | α ≥ 0.95 는 **실험적 문턱**(수학적 완전 소실 아님). 다른 프레임에서 드러나는 픽셀은 '시간 복원 가능'으로 따로 센다 |
| 평가 | Safety(재검사·위험 프레임 비율·새 위험) · Fidelity(PSNR·SSIM·LPIPS, 영역별) · Spatial(이음새·위험 밖 변경) · Temporal(광학 흐름 워핑 오차·변화량·질감) · Efficiency(p50/p95·FPS·GPU 메모리) | `src/lumi_synth/quality.py`, `scripts/eval_pipeline.py`. LPIPS 는 지각적 유사도이지 자연스러움이 아니다 — 어느 지표도 단독 합격 기준이 아니다 |
| 보정 구조 | B(마스크 조건부 하이브리드)를 목표, A(End-to-End)를 기준선 | E0 마스크 없음(`--no-mask`) · E1 판정기 튜브 · E2 탐지기 튜브 · E3 E2 + 손실 추정기(`train_roi --target loss`) 출력을 보정기에 한 채널 더(`--loss-input`) |
| 기준선 | 전체 감광 | 위험 프레임에서 화면 전체 시간 평균·흐림 (`eval_pipeline` 의 global) — '같은 위험 감소에서 원본을 얼마나 더 보존하나'를 보인다 |
| 남은 것 | 판정기 독립 검증(팀원 판별기·외부 도구), 실제 영상의 비참조 평가 | 미구현 |

## 검증용 모델

| | ROI 탐지기 `RoiNet` | 보정기 `Corrector` |
|---|---|---|
| 입력 | 영상 48프레임(2초), 768×432 | 영상 + 종류별 튜브 3채널 |
| 출력 | 종류별 튜브 확률 3채널, 1/4 해상도 | 보정 영상 = 입력 + 튜브·δ (튜브 밖은 구조적으로 입력 그대로) |
| 구조 | 프레임별 2D 줄기(1/2, 1/4) → 시간 dilation 블록 → 1/8·1/16 + 프레임별 화면 평균(면적 기준용) → 다시 1/4 | 같은 줄기·시간 블록 → 전체 해상도로 되돌림. 전역 연산 없음(조각으로 학습, 전체 화면에 사용) |
| 학습 목표 | 판정기 튜브(면적 평균) — BCE + 다이스 | **원본** — 튜브 안 L1 + 프레임 간 변화 L1 |

- 보정 목표를 '원본'으로 둔 것은 이 검증의 선택이다. PLAN §2 의 B 정답('판정기가 안전이라 하는 한도에서 가장 적게 고치기')은 아직 구현하지 않았다.
- 대조군 `rule_correct`: 튜브 안에서 앞뒤 0.5초 시간 평균(휘도·적색), 공간 흐림(줄무늬). PLAN §1: "딥러닝은 규칙 보정보다 빠르거나 더 자연스러울 때 의미가 있다."
