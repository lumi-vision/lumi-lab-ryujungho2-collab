# 전체 워크플로우 — 규칙 → 오라클 → GAN → 데이터셋

> 이 문서 하나로 프로젝트 데이터 파이프라인을 설명할 수 있게 쓴다. 세부는 각 문서로 연결한다.

## 0. 한 문단 요약 (발표용)

광과민성 발작 위험 영상을 **찾고(탐지) 그 부분만 고치는(국소 보정)** 모델을 만들려면, "화면 **어디가, 언제** 위험한지" 정답이 붙은 영상이 필요하다. 실제 위험 영상은 드물고 라이선스·윤리 문제가 있다. 그래서 깨끗한 영상에 깜빡임을 **합성**하고, 정답은 국제 표준(ITU-R BT.1702)을 수식으로 옮긴 **판정 규칙**으로 매긴다. 합성은 두 가지다. **오라클**은 조건을 정확히 통제해 경계 사례와 평가 기준을 만들고, **GAN** 은 같은 물리 모델·같은 규칙 아래에서 더 자연스럽고 다양한 빛을 만든다. GAN 이 규칙의 빈틈을 이용하지 않도록 모든 출력은 하드 판정으로 다시 라벨링한다.

## 1. 큰 그림

```
                 ┌──────────────── ① 판정 규칙 measure.py (ITU-R BT.1702, docs/RULES_SPEC.md) ───────────────┐
                 │   하드 판정: 라벨       소프트 판정(gan.py): GAN 학습 목표      외부 검증: pse-test-media     │
                 └───────▲──────────────────────────▲──────────────────────────────────────▲───────────────┘
                         │ 라벨                      │ 목표                                   │ 라벨
 Blender 영화(CC BY) ─► ② 바탕 클립 (data.py) ─┬─► ③ 오라클 (oracle.py) ──► 오라클 샘플 (Y, X, M, 정답)
   BBB: train/val        깨끗함 = 화면 전이 0   │      X = Y + M·w(t)·δ        의도 4종 경계 쌍
   ED : test                                   │
                                               └─► ④ GAN (gan.py) ─────────► GAN 샘플 (Y, X_G, M, 정답)
                                                      X = Y + M·Δ_G(Y,M,c,z)   위험 / 문턱 근처 안전
                                                                    │
                                     ⑤ 탐지·보정 모델 학습 (다음 단계, 아직 안 함)
                                        오라클만 vs 오라클+GAN → 실제 영상 시험셋에서 비교 (가설 H1)
```

## 2. 단계별 — 무엇을, 왜, 어떻게 확인하나

| 단계 | 입력 → 출력 | 왜 이렇게 | 확인 방법 |
|---|---|---|---|
| ① 규칙 | 영상 → 위험 여부, 화면 전이, '언제·어디' 정답 | 정답의 기준이 하나여야 오라클·GAN·라벨이 일관된다. 모호한 곳(D1~D4)은 근거와 함께 못 박음 | `tests/` 경계값·사례 테스트, `checks/rules/README.md` (pse-test-media 기대값 대조) |
| ② 바탕 | 영화 → 2초 클립 | 측정되는 깜빡임이 모두 우리가 넣은 것이어야 함 → 화면 전이 0 만 통과 | `checks/oracle/128x72_24fps.md` 의 분할별 바탕 수 |
| ③ 오라클 | 바탕 + 조건 → 합성 + 정답 | 선형 빛 더하기로 ΔL·면적·주파수를 정확히 통제 → 조건 하나만 다른 경계 쌍 | 의도-판정 일치율, 불일치 원인 (`checks/oracle`) |
| ④ GAN | 바탕 + 마스크 + 목표 + z → 합성 + 정답 | 오라클의 단조로움 보완. E1 붕괴를 피하려 오라클을 따라 하지 않고 규칙을 목표로 학습 | 조절력·대리 판정 신뢰도·다양성·국소성·자연스러움(코드 지표만, 사람이 보지 않음), 대조군(학습 안 한 G)·오라클 기준선 (`checks/gan`) |
| ⑤ 모델 | 오라클/GAN 샘플 → 탐지·보정 | GAN 의 효과는 여기서만 증명 가능 | 아직 안 함 |

## 3. 실행 순서 (명령)

```powershell
pip install -r requirements.txt          # numpy, opencv, matplotlib, pytest, 이 저장소(lumi_synth)
pip install torch                         # GAN (집 PC 는 CUDA 빌드: --index-url https://download.pytorch.org/whl/cu132)

# 원본 받기 (DATA_SOURCES.md, SHA256 확인)
#   data/raw/BigBuckBunny_640x360.m4v, data/raw/elephantsdream-480-h264-st-aac.mov

pytest                                                     # 1. 규칙·오라클·GAN 테스트
python scripts/validate_rules_pse.py --pse-root <pse-test-media 경로>   # 2. 규칙 외부 검증
python scripts/make_oracle_dataset.py                      # 3. 바탕 + 오라클 데이터셋 (노트북 약 6분)
python scripts/train_gan.py --steps 500 --batch-size 4 --scale 0.5     # 4. GAN 학습 (노트북 동작 확인 약 20분)
python scripts/eval_gan.py --scale 0.5                     # 5. GAN 평가 + GAN 데이터셋 저장
```

집 PC 본 학습 예: `python scripts/train_gan.py --device cuda --steps 4000 --batch-size 8 --width 32 --scale 1.0` (아직 실행 안 함)

## 5. 예상 질문과 답

- **오라클이 있는데 왜 GAN?** 오라클은 마스크 안이 균일하고 파형이 정해진 식이라, 탐지 모델이 깜빡임이 아니라 '덮어씌운 티'를 외울 수 있다. GAN 은 같은 규칙 아래에서 빛의 공간 분포·리듬을 다양하게 만든다. 효과는 H1 실험으로 검증해야 하며 아직 주장하지 않는다.
- **GAN 이 오라클을 배우면 되지 않나?** 그렇게 했던 E1 에서 G 가 오라클 평균판으로 붕괴했다(z 를 바꿔도 세기 표준편차 0.0004). Barbu(2020) 구현에서도 같은 현상이 보고됐다.
- **규칙 기반이면 IRIS 와 같은 것 아닌가?** 판정 기준은 같은 표준에서 왔지만, IRIS 는 프레임 판정과 사각형만 준다. 우리는 픽셀 단위 마스크·시간 정답을 직접 넣어서 확실히 안다. 또 IRIS 는 화면 평균으로 재서 국소 깜빡임과 체커보드 반전을 놓친다(D2 표).
- **라벨이 틀릴 수는 없나?** 라벨은 규칙의 결과라서 규칙이 틀리면 틀린다. 그래서 규칙을 수식으로 명세하고, 경계값 테스트와 외부 기대값(pse-test-media) 대조로 검증한다.
- **GAN 이 규칙의 빈틈을 이용하면?** 학습은 소프트 판정으로 하지만 라벨은 하드 판정으로 다시 매긴다. 두 판정의 일치도를 매번 기록한다.
- **임상적으로 안전하다는 뜻인가?** 아니다. 표준 문턱을 넘느냐의 판정이다.
