# 판정 규칙 명세 (Rules Spec) — 휘도 깜빡임, ITU-R BT.1702 일반 깜빡임

> 코드: `src/lumi_synth/measure.py` (`analyze`) · 테스트: `tests/test_measure.py`, `tests/test_rules_oracle_gan.py`
> 외부 검증: `checks/rules/README.md` (pse-test-media 의 표준별 기대값과 대조)
> 이 규칙 하나가 오라클의 정답, GAN 의 학습 목표, 데이터셋 라벨을 모두 정한다.

## 1. 왜 규칙을 수식으로 못 박나

데이터셋의 '정답'은 이 규칙이 만든다. 규칙이 모호하면(예: 두 프레임에 걸친 변화를 몇 번으로 셀지) 같은 영상에 사람·코드마다 다른 정답이 붙고, GAN 은 그 빈틈을 이용하는 쪽으로 학습될 수 있다. 그래서 모든 단계를 기호와 부등호(경계 포함 여부)까지 정한다.

## 2. 기호

| 기호 | 뜻 |
|---|---|
| t = 0…T−1, p | 프레임 번호, 픽셀 |
| f | 프레임 속도(fps). W = round(f) = 1초 창의 프레임 수 |
| L[t,p] | 물리 휘도 (cd/m²) |
| s[t,p] ∈ {−1,0,+1} | 픽셀 전이 (−1 어두워짐, +1 밝아짐) |
| c | 동시성 창 = max(1, round(f/15)) 프레임 (30 fps → 2) |
| A↑[t], A↓[t] | 최근 c 프레임 동안 밝아진/어두워진 픽셀의 면적 비율 |
| e[t] ∈ {−1,0,+1} | 화면 전이 |

## 3. 정의

**(1) 휘도.** sRGB 값을 IEC 61966-2-1 식으로 선형화하고 L = 200 · (0.2126 R + 0.7152 G + 0.0722 B).

**(2) 픽셀 전이 (히스테리시스).** 픽셀마다 기준값 ref 와 방향 dir 을 둔다(처음 ref = L[0], dir = 0).
프레임 t 에서 v = L[t,p]:
- 같은 방향으로 더 가면(dir = +1 이고 v > ref, 또는 dir = −1 이고 v < ref) ref ← v (극값 추적).
- 그렇지 않고 |v − ref| **≥ 20** 이고 min(v, ref) **< 160** 이고 sign(v − ref) ≠ dir 이면
  s[t,p] = sign(v − ref), dir ← s[t,p], ref ← v.

→ 여러 프레임에 걸친 느린 변화도 극값 대비로 재므로 '한 번'으로 센다.

**(3) 방향별 동시 면적.** A↑[t] = |{p : ∃ τ ∈ [t−c+1, t], s[τ,p] = +1}| / (H·W), A↓ 도 같은 방식.

**(4) 화면 전이 (상태 기계).** state = 0 에서 시작. 각 t 에서
- 후보 ↑ ⇔ A↑[t] **> 0.25** 이고 프레임 t 에 s = +1 인 픽셀이 하나 이상 (새 전이)
- 후보 ↓ 도 같은 방식
- 한 방향만 후보 → d = 그 방향. 두 방향 모두 후보 → d = −state (state = 0 이면 넓은 쪽)
- d ≠ state 이면 e[t] = d, state ← d. 같으면 세지 않음.

**(5) 위험.** N(s) = Σ_{t=s}^{s+W−1} |e[t]| (아무 1초 창의 화면 전이 수). max_s N(s) **≥ 7** (= 깜빡임 > 3) 이면 위험.

**(6) 위치·시간 정답.** 위험 창(N(s) ≥ 7)에 속한 프레임 = `hazard_frames`.
그 창 안의 화면 전이 e[t] 마다, 최근 c 프레임에 e[t] 방향으로 전이한 픽셀의 합집합 = `hazard_mask`.

## 4. 설계 결정과 근거

| # | 결정 | 근거 | 대안과 한계 |
|---|---|---|---|
| D1 | 같은 방향 화면 후보가 이어지면 1번 | 한 번의 변화가 두 프레임에 나뉘어 그려지는 경우(진행 주사, 움직임, 인코딩)가 흔하다. 이전 구현은 이를 2번으로 세어 **초당 1.88번(안전)을 4번(위험)으로 판정**했다(2026-11-09 시험, 테스트 `test_d1_*`). | 서로 다른 영역이 차례로 밝아졌다 어두워져도 화면 기준 1번 깜빡임으로 센다(보수적). |
| D2 | 면적은 방향별 | 초기화 전 같은 정의의 판정기가 pse-test-media ITU 기대값 56/56 과 일치. 결과는 `checks/rules/README.md` 에서 다시 확인. | 15% 밝아짐 + 15% 어두워짐이 동시에 일어나면 위험으로 보지 않는다. IRIS(화면 평균)는 체커보드 반전 자체를 못 본다. |
| D3 | 동시성 창 c = round(f/15) | 두 프레임(30 fps 에서 67 ms)에 걸친 하나의 변화를 '동시'로 본다. 20%+20% 로 나뉜 변화가 0번이 되는 것을 막는다(`test_d3_*`). | 서로 무관한 두 부분 변화가 67 ms 안에 같은 방향으로 겹치면 합쳐진다(보수적). |
| D4 | 두 방향 동시 후보는 1번 + '새 전이' 조건 | 체커보드 반전 1번 = 각 칸의 밝기 변화 1번. '새 전이' 조건이 없으면 창 c 때문에 같은 반전을 두 프레임 연속 세어 5 Hz 를 10번으로 셌다(`test_d4_*`). | — |
| A1 | sRGB 전달 함수, 흰색 200 cd/m² | ITU·WCAG 계산 관례. | 영상의 BT.709/BT.1886, HDR, 실제 표시 장치 밝기는 반영하지 않는다. |
| A2 | 면적 = 화면 비율 | 시야각 기반 면적(시청 거리·화면 크기)은 이번 범위 밖. | 큰 화면·가까운 시청에서는 과소 평가될 수 있다. |

## 6. 범위 밖
