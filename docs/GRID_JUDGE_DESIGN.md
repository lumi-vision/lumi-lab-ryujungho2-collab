# 격자 판정기 설계 — "측정은 픽셀, 판단·설명은 격자" (2026-11-24, 사용자 결정)

> 목표: 결론마다 **"화면의 어느 칸에서, 무엇이, 규격의 어느 조항을 얼마나 넘었나"** 를 말할 수 있는 판정기.
> 비교: 팀원 Partial B2 원본(v1, 기준) · 패치판 `lumi_judge`(v2) · 격자 판정기(G). 모든 변경은 '무엇을 · 왜(조항/근거 등급) · 효과(수치)' 한 줄로 쌓는다.
> 근거 등급: **원문**(표준·논문 직접 확인) · **실험**(우리 저장소의 측정) · **구현 선택**(문헌에 수치 없음 — 민감도 분석 의무).

## 0. 왜 격자인가 — 논리
1. **설명 가능성**: 규격의 조건(면적 %, 쌍 수, 밝기 차, 횟수/초)은 모두 '화면의 어느 부분에서 무엇이' 로 진술된다. 격자는 그 진술의 단위가 된다.
2. **오류 발견 가능성**: v1 의 패턴 면적 오류(화면 전체 대비 면적을 패턴 면적처럼 씀)는 복잡한 경로 안에 숨어 있었다(실험: `checks/judge/pattern_trace.md`, 오탐 24 클립의 실제 패턴 면적 중앙값 4.5 % 인데 판정 면적 73 %). 칸별 중간 결과가 있으면 이런 오류가 표 한 장으로 드러난다.
3. **GPU 적합성**: 칸별 측정은 처음부터 텐서 연산이다(단면별 순차 반복 없음).
4. **단, 평균은 금지**: 화면(또는 칸) 평균 밝기로 깜빡임을 세면 국소 깜빡임을 놓친다(실험: `docs/LESSONS.md` A2 — 25 % 패턴의 평균 변화는 1/4 로 줄어 누락). → **측정은 픽셀 단위로 규격대로 하고, 격자는 그 결과를 모아 판단·설명하는 데만 쓴다.**

## 1. 격자
- 해상도와 무관하게 **화면 비율 기준 32 × 18 칸**(16:9; 칸 하나 = 화면의 1/576 ≈ 0.17 %). 다른 비율은 칸이 정사각에 가깝도록 열 수 조정.
- 근거: 규격 면적 문턱은 25 %·40 %(원문). 칸 단위로 면적을 셀 때 경계 칸 오차를 피하려고 **면적은 픽셀에서 정확히 세고**, 칸은 '어디'를 말하는 단위로만 쓴다 → 칸 크기는 설명 해상도의 문제이지 판정 정확도의 문제가 아니다. 32 × 18 은 구현 선택(민감도: 16 × 9 · 64 × 36 에서 판정 동일성 확인).
- 칸마다 기록: 그 칸에서 규칙을 만족한 픽셀 비율(0–1) — 지도·근거 출력용.

## 2. 측정량 (픽셀 → 칸)
| 대상 | 픽셀 측정(규격대로) | 칸 요약 | 근거 |
|---|---|---|---|
| 밝기 | sRGB → 선형 → cd/m² (피크 백색 200 cd/m², 감마 2.2 가정) | 평균·최소·최대 | 원문(ITC 각주: 감마 2.2, 피크 200 cd/m², BT.500) |
| 휘도 전이 | 픽셀별 히스테리시스 ±20 cd/m², 어두운 쪽 < 160 cd/m² (HDR 은 1/17 Michelson) | 전이 픽셀 비율 | 원문(BT.1702-3 Guideline 1) |
| 적색 전이 | 포화 적색 상태 변화(팀원 판의 정의 유지) | 전이 픽셀 비율 | 원문(BT.1702-3: 포화 적색으로의/으로부터의 전이) + 팀원 판 구현 |
| 줄무늬 | 칸 중심 창(칸의 2 배 크기)에서 국소 방향(구조 텐서)·주기(그 방향 단면의 자기상관)·밝기 진폭·규칙성 | 방향 θ, 파장 λ, 진폭 ΔL, 규칙성 r | 원문(정의: "clearly discernible stripes in any orientation, parallel or radial, curved or straight") + 구현 선택(창 크기·규칙성 문턱) |

## 3. 판단 규칙 (조항별)
**F1 휘도 깜빡임** — 같은 프레임(동시성 창) 안에서 같은 방향으로 전이한 픽셀이 화면 > 25 % 인 순간을 '화면 전이' 로 세고, 1 초 창에 화면 전이가 > 6(= 깜빡임 > 3 회)이면 위험. (원문: BT.1702-3 Guideline 1, 25 %, 3 회/초) — 칸 지도: 그 순간 전이 픽셀이 있는 칸.
**F2 적색 깜빡임** — F1 과 같은 면적·횟수 규칙을 포화 적색 전이에. (원문)
**F3 연장 깜빡임** — 5 초 창 안에서 전이 4–6 회가 4 초 이상 지속(팀원 판 / EA IRIS 파라미터 유지). (구현 선택 — IRIS 근거)
**P1 정적 패턴** — ① 줄무늬 칸: ΔL ≥ 20 cd/m²(어두운 막대 < 160), 규칙성 r ≥ r₀ ② 이웃 칸 연결: λ 비 ≤ 1.5, 방향 차 ≤ 20°(곡선·방사는 방향이 연속적으로 변하므로 '이웃끼리' 만 비교) ③ 영역의 쌍 수 = 영역의 법선 방향 길이 / λ > 5 ④ **영역의 픽셀 면적 > 40 %**(정지) ⑤ 0.5 s 이상 지속. (원문: ①③④ ITC/Ofcom·BT.1702-3 Att.1, ⑤ Harding FPA 해설 · 구현 선택: r₀·λ 비·방향 차)
**P2 변화 패턴** — 같은 영역이 방향 전환·진동·점멸·대비 반전이면 면적 문턱 25 %. **한 방향으로 매끄럽게 흐르면 면제**(칸별 위상의 시간 변화가 한 방향 일정 속도). (원문)

## 4. 출력 — 근거가 붙은 판정
```json
{"label": "정적 공간 패턴", "start_s": 3.2, "end_s": 5.1,
 "clause": "ITC/Ofcom Annex1 §5.1(i) · BT.1702-3 Att.1",
 "evidence": {"area_pct": 46.3, "pairs": 9, "delta_cd_m2": 85, "dark_bar_cd_m2": 12, "wavelength_px": 21,
              "orientation": "radial", "cells": [[12,4],[13,4], "..."]},
 "map_png": "…/pattern_t3.2.png"}
```
에이전트·사용자에게는 이 근거를 문장으로: "3.2–5.1 초, 화면 46 %(빨간 칸)에 방사형 줄무늬 9 쌍, 밝기 차 85 cd/m² → 정지 패턴 기준(40 %, 5 쌍, 20 cd/m²) 초과".

## 6. 단계와 기록 형식
1. F1·F2 (픽셀 측정은 팀원 판 재사용 → 격자 요약·근거 출력) — v1 과 깜빡임 판정 일치 확인
2. P1 (칸별 줄무늬 측정 → 영역 → 규칙) — 적합성 시험 → 일상 영상 오탐 → v1·v2 비교
3. P2 (흐름 면제·변화 패턴)
4. F3
