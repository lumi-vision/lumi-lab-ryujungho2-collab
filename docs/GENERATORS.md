## 1. 한 줄 요약

G 는 **영상을 새로 그리지 않는다.** 깨끗한 바탕 영상 Y 와 허용 영역(마스크) M 을 받아, 정해 둔 물리식에 넣을 **'얼마나'(필드)** 만 시간·공간별로 정한다. 마스크 밖은 구조적으로 원본 그대로다. 목표(위험 / 근처 안전)는 미분 가능한 판정기(소프트 판정)로 맞추고, 학습 뒤에는 하드 판정기로 다시 잰다. **정답(라벨)은 늘 하드 판정기가 붙인다 — 생성 의도는 정답이 아니다.**

```
바탕 Y ─┐
마스크 M ─┼─► G 몸통(LightGenerator: 공간 1/4 → 시간 팽창 합성곱 → 확대) ─► 필드 F(t,p) ∈ [0,1] 또는 빛 Δ
목표 c ──┤                                                                         │
잡음 z ──┘ (z 일부는 '조건'으로도 쓰임 — §4)                                         ▼
                                              종류별 섞는 식(선형 빛): X = (1 − M·α)·Y + M·α·P  (휘도는 Y + M·Δ)
                                                                                    │
                       학습: 소프트 판정 손실 + 적대 손실(D: 프레임 한 장) + 다양성 손실 ◄─┘
                       평가·라벨: 하드 판정기 measure.analyze / analyze_red / stripe_freq(쿼드트리+가버)
```

## 3. G 의 종류 (지금 쓰는 것은 굵게)

종류(`config.hazard`)마다 따로 학습한다. 몸통은 모두 `LightGenerator` 이고 섞는 식과 조건만 다르다. 모두 768×432·24 fps, train 바탕 60클립으로 학습, val 12클립 × 목표 2 × z 4 = 96개로 평가.

### 3-1. 휘도 깜빡임 — 섞는 식 X_lin = Y_lin + M·Δ (흰 빛을 더함, Δ ≤ 120 cd/m²)

| 체크포인트 | 학습 옵션 | 무엇이 다른가 | 위험 → 위험 / 근처 → 안전 |
|---|---|---|---|
| `w_div2.0_2k_s0` | `--hazard lum --lambda-div 2 --steps 2000` | v1. 판정 규칙(20 ms 동시성 창) 반영 | 48/48 · 48/48 |
| **`w2s_div2.0_1k_s0`** | v1 + `--lum-smooth --steps 1000` | v2. z 의 마지막 성분으로 시간 흐림 σ 0~2 프레임 → 사인·삼각파꼴 깜빡임도. v1 은 사각파꼴뿐이어서 탐지기가 규칙 생성기의 사인파를 놓쳤다 | 39/48 · 44/48 |
| `u_*`, `u2k_*`, `ufp32_*` | (11-14 이전) | 옛 판정 규칙(2프레임 동시성 창)으로 학습 — 쓰지 않음 | – |

### 3-2. 적색 깜빡임 — X_lin = (1 − M)·Y + M·[(1 − ρ)·O + ρ·R]

ρ(t,p) = G 가 정하는 '빨강 정도'. R = 포화 빨강(R/(R+G+B) ≥ 0.84), O = 빨강 아닌 상태.

| 체크포인트 | 학습 옵션 | 무엇이 다른가 | 위험 → 위험 / 근처 → 안전 |
|---|---|---|---|
| `r_div2.0_s0` | `--hazard red` | v1. O = 장면 그대로, R = 장면과 같은 휘도의 순수 빨강 | 42/48 · 46/48 |
| `r_crisp2_div2.0_s0` | + `--lambda-crisp 2` | v1 + 켜짐·꺼짐을 한 프레임에 끝내게(하드 판정의 쌍 짓기와 맞춤) | 45/48 · 46/48 |
| `r2_crisp2_div2.0_s0` | + `--red-palette` | v2. 색 조건 9개를 작은 MLP 가 고름 → 가운데로 몰려 실패 | 43/48 · 39/48 |
| `r3z_crisp2_div2.0_s0` | `--red-palette z --zdim 12` | v3. 색 조건을 z 에서 균등하게(도메인 무작위화) | 37/48 · 40/48 |
| **`r4z2_crisp2_div2.0_s0`** | `--red-palette z2 --zdim 12` | v4. v3 + 등휘도(빨강 휘도를 O 쪽으로) + 조건 양 끝값 14% 씩. v1 데이터로 학습한 탐지기는 규칙 생성기의 '평평한 빨강 ↔ 보라'(등휘도) 를 24개 중 1개만 찾았다 | 28/48 · 35/48 |

### 3-3. 줄무늬 — X_lin = (1 − M·a)·Y + M·a·S

a(t,p) = G 가 정하는 '덮는 정도'. S = 무늬(어두운 줄 10 cd/m² ↔ 밝은 줄 80~140 cd/m²). 무늬 자체는 식으로 그리므로 cpd 대역과 규칙성은 구조상 지켜진다.

| 체크포인트 | 학습 옵션 | 무엇이 다른가 | 위험 → 위험 / 근처 → 안전·보임 |
|---|---|---|---|
| `s_div2.0_s0` | `--hazard stripe` | v1. 조건(cpd·방향·속도·밝기)을 MLP 가 고름. 직선, 정지·흐름만 | 48/48 · 48/48 |
| `s2z_div2.0_s0` | `--stripe-cond z` | v2. 조건 무작위 + 명암 반전, 줄 모양·반전 파형(사인 ↔ 사각). '정지' 인데 덮는 정도가 깜빡이는 문제 | 48/48 · 45/48 |
| `s3z2_div2.0_s0` | `--stripe-cond z2 --zdim 10` | v3. 덮는 정도에 시간 흐림 σ 0~12 프레임 → 진짜 정지 줄무늬 | 48/48 · 48/48 |
| `s4dc_from_s3z2` | (학습 없음: v3 가중치 + `stripe_cond=z2dc`) | v4. 절반 클립의 픽셀 깜빡임을 2.5 Hz 이하로 → 휘도 위험 없는 반전·흐름 줄무늬. 통제 실험에서 휘도 → 줄무늬 오탐 21 → 6 | 48/48 · 48/48 |
| **`s5pat_div2.0_s0`** | `--stripe-cond z3 --zdim 14` | v5. v4 + 무늬 7종(직선·동심원·방사형·나선·처프·체커·물결), 중심 위치 무작위 | 41/48 · 44/48 |

- 체커는 지금 줄무늬 판정기(쿼드트리+가버)가 줄무늬로 보지 않는다 → 정답은 '줄무늬 위험 없음'. 체커를 기준에 넣을지 미결.
- 방사형은 중심 근처 국소 cpd 가 10 을 넘어 그 부분은 줄무늬로 세지 않는다.

## 4. z 의 쓰임 (조건을 z 에서 뽑는 버전)

z ~ N(0, 1). '조건'으로 쓰는 성분은 Φ(z)(정규 누적분포)로 0~1 균등값이 된다. 조건 성분도 FiLM 으로 몸통에 들어가므로 G 는 주어진 조건에 맞춰 필드를 정한다.

| G | z 성분 → 의미 |
|---|---|
| 휘도 v2 (zdim 8) | z[−1] → 시간 흐림 σ (0~2 프레임). 나머지는 잡음 |
| 적색 v3 (zdim 12) | z[0..8] → 채도 · 빨강 평평함 · 빨강 밝기 · 물듦 κ · O 의 색 방향 B·G·R · O 평평함 · O 밝기 |
| 적색 v4 (zdim 12) | v3 + z[9] → 등휘도 ι, 모든 조건을 [−0.2, 1.2] 로 늘려 자름(양 끝 14%) |
| 줄무늬 v2 (zdim 8) | z[0..7] → cpd(로그 1.3~7) · 방향 0~360° · 움직임(정지/반전/흐름 1/3 씩) · 흐름 1~6 °/s · 반전 2~10 Hz · 밝은 줄 · 줄 모양 g · 반전 파형 g |
| 줄무늬 v3 (zdim 10) | v2 + z[−1] → 덮는 정도 시간 흐림 σ 0~12 프레임 |
| 줄무늬 v4 (zdim 10) | v3 + z[8] < 0 → 픽셀 깜빡임 ≤ 2.5 Hz (반전 0.5~2.5 Hz, 흐름 ≤ 2.5/cpd °/s) |
| 줄무늬 v5 (zdim 14) | v4 + z[9] → 무늬 종류 · z[10], z[11] → 중심 x·y (화면 25~75%) · z[12] → 처프 정도·물결 진폭/파장·나선 방향 · z[−1] → 시간 흐림 |

같은 z(= 같은 z_seed)와 같은 바탕·마스크면 같은 영상이 나온다. 표본을 레시피로 다시 만들면 저장된 영상과 차이가 0 이었다(1,392개 확인).

## 5. 실행 논리

### 5-1. 학습 한 스텝 (`scripts/train_gan.py`)

1. train 바탕에서 클립 B 개, 마스크(`sample_masks`: 오라클 모양, 면적 0.32~0.70 · 줄무늬 0.45~0.85), 목표 c(위험·근처 반반), 잡음 z1·z2 를 뽑는다.
2. D 갱신: 진짜 = 깨끗한 바탕 프레임, 가짜 = G 출력 프레임(무작위 4장). 힌지 손실.
3. G 갱신: `손실 = λ_judge·판정 + λ_adv·적대 + λ_div·다양성 (+ 적색 λ_crisp·또렷함)`
   - 판정(종류별): 휘도 `soft_judge`(1초 전이 ≥ 8 / 근처 2~5), 적색 `soft_judge_red`(같은 횟수, 색도 차 0.2·포화 0.8 을 시그모이드로), 줄무늬 `soft_judge_stripe`(면적 > 40% 지속 ≥ 0.7초 / 근처 ≤ 0.25초이면서 보임 — 픽셀이 아니라 G 가 정한 값으로 계산하는 대리 판정)
   - 다양성: z1·z2 출력의 시간 스펙트럼 차이 / z 차이(휘도·적색·줄무늬 v2+), 조건 차이(줄무늬 v1, 적색 v2)
4. 체크포인트에 학습 설정 전체, 판정 규칙(`judge_rule`: 동시성 창 20 ms, 1초 창), 학습 해상도·fps 를 기록. **같은 이름이 있으면 멈춘다**(`--overwrite` 로만 덮어씀).

GPU 설정(RTX 5080 16 GB): `--device cuda --grad-ckpt --batch-size 4 --micro-batch 1`, 500스텝 약 13~25분(다른 GPU 작업과 겹치면 몇 배 느려짐).

### 5-2. 평가 (`scripts/eval_gan_hazards.py --checkpoint data/gan/<이름>.pt [--scanline N]`)

val 12클립 × 목표 2 × z 4 를 하드 판정으로 재고, 같은 구조의 학습 안 한 G 와 비교한다: 목표 적중, 근처 안전이 '보이는지', 대리 ↔ 하드 일치, 다른 종류 위험 동반, 마스크 밖 변화(0 이어야 함), z 다양성, 줄무늬는 움직임별·무늬별.

### 5-3. 추론 (`src/lumi_synth/generate.py`)

```
sample_recipe("gan", 의도, seed, checkpoint=…, split, bg)      # 마스크 모양·면적·중심, z_seed 를 seed 에서
  → render(recipe, clean, fps)
      → gan_render: 체크포인트 config(hazard, red_palette, lum_smooth, stripe_cond)로 make_generator → G(Y, M, c, z)
         (해상도·fps 가 학습과 다르면 거부, GPU 여유 4 GB 미만이면 CPU)
      → 합성 비중 α (원본 대신 합성한 몫: 휘도 = 255 포화 채널 비율, 적색 = 1 − (1−κ)(1−ρ), 줄무늬 = a)
  → make: npz 저장 (clean, flicker, mask_allow, mask_changed, fps, intent_hazard, recipe — schema 2)
```

- 플레이어 생성, 확인용 묶음(`make_review_set.py`), 탐지·보정 데이터(`make_gdr_dataset.py`)가 모두 이 경로를 쓴다.
- 데이터 생성에서는 하드 판정기(`roi.judge_tubes`)가 종류별 위험 영역(튜브)을 정답으로 붙이고, α 를 `<id>.alpha.npz` 로 따로 저장한다.

## 6. 알려진 한계

- **겉모습이 자연스럽지 않다.** 마스크 경계가 날카롭고 덮는 빛·색·무늬가 장면과 무관하게 평평하다. 적대 손실 가중치가 0.1 이고 D 가 깨끗한 프레임 한 장만 본다 — 자연스러움은 아직 학습 목표가 아니다.
- 다양성을 넓힌 버전일수록 목표 적중률이 떨어진다(적색 v4 58%, 휘도 v2 81%). 정답은 판정기가 붙이므로 데이터로는 쓸 수 있다.
- 24 fps 라 15~20 Hz 깜빡임을 만들 수 없고, 줄무늬 흐름의 픽셀 깜빡임이 12 Hz 를 넘으면 겹침(에일리어싱)이 생긴다 → 60 fps 트랙 필요.
- 줄무늬 소프트 판정은 픽셀을 보지 않는 대리 판정이라 하드 판정과 어긋날 수 있다(v5 88/96 일치).
- 시드 1개 학습이다. 탐지 실험에서 같은 데이터로도 시드에 따라 규칙 적색 17 ↔ 22/24 가 나왔다.
