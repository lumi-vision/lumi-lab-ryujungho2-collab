# Phase 1.1 시간축 검증

2026-11-18. 기존 코드는 원본에서 선택한 프레임의 상대 시간이 정확히 1ms의 배수여야 한다고 명시적으로 검사했고, 그렇지 않으면 MKV를 만들기 전에 실패했다. 24fps의 1/24초는 이 조건을 만족하지 않는다. 또한 출력이 실제로 사용할 컨테이너 time base를 확인하지 않고 동일 시간이라고 가정했다.

현재는 Source(원본·원본 해시), Canonical(virtual clip의 정수 PTS·time_base 및 프레임 인덱스), Model Input(G용 NPZ)을 분리한다. virtual clip은 비디오 재인코딩 없이 원본의 모든 PTS 단조성을 검사하고 반열린 구간 `[start,end)`을 참조한다. 원본 절대 시간과 선택된 첫 프레임 기준 상대 시간은 유리수 문자열이다. 마지막 프레임의 지속시간은 unknown으로 기록한다.

선택적 FFV1/MKV 출력은 상대 시간을 1ms로 반올림한다. 역디코딩한 각 출력의 실제 PTS/time_base와 원본 상대 시간의 차이를 기록하며, 프레임 수·순서·BGR 픽셀·양자화 후 시간의 왕복이 실패하거나 시간 충돌이 있으면 오류다. MKV 시간은 원본 시간이 아니며, PTS는 평균 fps로 복원하지 않는다. 선택적 크기 변환 및 BGR 변환이 있으므로 원본의 원래 색 공간을 바이트 그대로 보존하는 절차는 아니다. virtual clip은 원본의 참조를 보존하므로 실파일이 계속 존재해야 한다.

`export_virtual_backgrounds`는 원본 해시·프레임 인덱스·PTS를 재검사해 정확히 일정한 fps의 프레임만 기존 G용 NPZ로 내보낸다. 크기 조정·VFR 재표본화는 하지 않는다. 모델 입력은 원본 시간 정보 보존 결과가 아니다.

`python -m pytest tests/test_dataset_timing.py tests/test_dataset_phase1.py -q`: 14 passed. `python -m pytest -q`: 192 passed, 1 skipped, 1 warning (2026-11-18). 테스트는 24, 25, 30, 24000/1001, 30000/1001, 60fps, VFR, 시작 PTS 2초, 경계, PTS 누락·중복·비단조를 다룬다. 정상 시험 원본은 NUT/FFV1이며 출력은 MKV/FFV1로 실제 인코딩·디코딩했다. 출력 오차 상한은 0.5ms로 검증했다. 누락·비단조 입력은 가짜 프레임 객체로 단위 시험했고 해당 오류가 들어간 실제 손상 컨테이너는 시험하지 않았다. 기존 G 로더로 24fps virtual 원본에서 만든 소형 NPZ를 읽었다. 기존 전체 테스트에는 별도의 기존 합성 함수 단위 테스트가 포함되지만 실행·저장되는 위험 영상이나 모델 학습은 수행하지 않았다.

남은 한계: 선택 프레임을 메모리에 보관하므로 큰 클립에서 메모리 사용량이 크다. 가상 클립 JSON은 현재 일반 manifest의 계보 레코드로 자동 편입되지 않는다. 모든 코덱·VFR·HDR·색 메타데이터를 검증한 것은 아니고, 재인코딩된 유사 원본 탐지도 제공하지 않는다.
