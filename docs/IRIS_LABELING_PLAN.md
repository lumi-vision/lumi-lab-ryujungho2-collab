# IRIS 라벨링 계획 — 합성 데이터에 독립 검사 결과 붙이기

> 상태: **1~4단계 완료, 5단계 진행 전** · 작성 2026-11-05 · 확인 시험 결과 5.1절
> 목표: 지금 모든 샘플이 `risk_verified: false`인 문제를, 직접 만든 감지기가 아니라 **공개 검사기 IRIS의 판정**으로 채운다.

## 1. 왜 IRIS인가

합성(Oracle·GAN)은 위험 특성을 **입히는** 단계이고, 라벨링은 결과가 기준을 넘었는지 **판정하는** 단계다. 판정용 감지기를 직접 만들면 그 감지기부터 검증해야 하므로, 공개 검사기를 독립 판정자로 쓴다.

| 항목 | 내용 |
|---|---|
| 출처 | Electronic Arts, https://github.com/electronicarts/IRIS |
| 라이선스 | BSD-3-Clause (저작권 고지 유지, EA 명의 홍보 금지) |
| 언어·빌드 | C++, CMake + Ninja + vcpkg (OpenCV 의존) |
| 감지 | 휘도 깜빡임, 적색 깜빡임, 공간 패턴 |
| 판정 | 1초 안에 3회 초과 깜빡임 → 실패 · 5초 동안 초당 2~3회 → 연장 실패 · 패턴 0.5초 이상 → 실패 |
| 출력 | 프레임별 CSV(`-j 1`이면 JSON): 깜빡임 면적, 전환 횟수, 패턴 면적·선 수, 휘도/적색 프레임 결과(0 통과·1 경고·2 연장 실패·3 실패), 패턴 프레임 결과(0·1) |
| 한계 | IRIS 스스로 "인증·적합성 보증 아님"을 명시. 라벨 이름은 반드시 **IRIS 판정**으로 기록 |

## 2. 사용 방식: 소스 이식이 아니라 실행 파일 호출

- IRIS 소스를 Python으로 옮기지 않는다. 옮기면 원본과 같은 결과라는 보장이 사라진다.
- 빌드한 예제 콘솔 앱을 `subprocess`로 호출한다: `-v <영상> -j 1 -p 1`.
- 저장소에 IRIS 소스·실행 파일을 넣지 않는다. 실행 파일 경로는 환경 변수 `LUMI_IRIS_EXE`로 받는다.
- 재현용으로 **IRIS 커밋 해시**와 **`appsettings.json`의 SHA-256**을 모든 라벨에 기록한다. 기본 설정값은 바꾸지 않는다(바꾸면 IRIS의 감지 근거가 깨진다).
- IRIS는 미분할 수 없으므로 GAN 손실에 직접 넣지 않는다. 라벨링·필터링에만 쓰고, 손실이 필요하면 나중에 IRIS 라벨로 학습한 작은 대리 판별망(surrogate)을 쓴다.

## 3. 파이프라인

```
원본 영상 ─► Oracle/GAN 합성 (라벨용 긴 클립) ─► 무손실 영상 파일 ─► IRIS ─► 프레임별 JSON
                                                                              │
     manifest.jsonl ◄── iris 필드 기록 ◄── 클립·학습 창 라벨 계산 ◄────────────┘
                │
                └─► GAN·탐지 학습: 라벨이 붙은 긴 클립에서 16프레임 창을 잘라 사용
```

## 4. 현재 코드에서 바꿔야 할 것

| 항목 | 현재 | 변경 | 이유 |
|---|---|---|---|
| 클립 길이 | 16프레임 @24fps ≈ 0.67초 | 라벨용 클립 **6초 이상**(144프레임 @24fps) | IRIS 깜빡임 판정은 1초, 연장 판정은 5초 구간이 필요 |
| 학습 입력 | 클립 = 학습 단위 | 긴 클립에서 16프레임 창을 잘라 학습 | GAN 구조(16프레임 입력)는 그대로 유지 |
| 저장 형식 | `.npz` 배열만 | `.npz` + IRIS 입력용 **무손실 영상**(FFV1/MKV 우선) | 손실 압축은 깜빡임 세기를 바꿀 수 있음 |
| 시간 파형 | 클립마다 주파수 1개(0.8~10 Hz) | 6초 안에서 주파수·세기가 바뀌는 구간 포함 | 통과·실패·연장 실패가 섞여야 라벨 분포가 고름 |
| 해상도 | 128×96 | IRIS 패턴 감지가 이 해상도에서 동작하는지 먼저 확인(5절 시험 4) | 패턴 선 검출은 해상도 영향이 큼 |
| `type` 필드 | 합성 유형 = 정답처럼 보임 | 합성 유형은 **조건**, 정답은 IRIS 결과 | 예: `pattern` 합성은 움직이면서 휘도 깜빡임도 만들 수 있음 |

### manifest 추가 필드 (안)

```json
"iris": {
  "version": "<IRIS 커밋 해시>",
  "settings_sha256": "<appsettings.json 해시>",
  "video": "train/<id>.mkv",
  "frames_json": "train/<id>.iris.json",
  "luminance_max": 3, "red_max": 0, "pattern_max": 0,
  "fail_frames": {"luminance": [37, 38], "red": [], "pattern": []}
},
"risk_verified": true,
"standard_result": "iris:luminance_flash_fail"
```

- `risk_verified: true`는 "IRIS로 검사했다"는 뜻이지 "위험하다/안전하다"는 뜻이 아니다.
- IRIS 실행이 실패하면 `risk_verified: false`, `standard_result: "iris_error"`로 남기고 학습에서 제외한다(통과로 취급하지 않음).

## 5. 시작 전 확인 시험 (라벨러 검증)

IRIS를 정답 생성기로 쓰기 전에, 결과를 알고 있는 자극으로 동작을 확인한다.

| # | 자극 (6초, 화면 전체) | 기대 결과 |
|---|---|---|
| 1 | 흰↔검 4 Hz 깜빡임 | 휘도 실패(3) |
| 2 | 흰↔검 1 Hz 깜빡임 | 통과(0) |
| 3 | 흰↔검 2.5 Hz, 6초 지속 | 연장 실패(2) |
| 4 | 정지 흑백 줄무늬, 128×96과 640×480 두 해상도 | 패턴 실패(1). 해상도별 차이 기록 |
| 5 | 순적↔검 4 Hz | 적색 실패(3) |
| 6 | 화면 10% 영역만 4 Hz | 면적 기준 미달로 통과 예상(IRIS 면적 기준 확인) |
| 7 | 1번을 무손실 MKV와 손실 MP4로 각각 | 결과 동일 여부 확인 → 저장 코덱 결정 |

이 시험 영상은 광과민성 유해 자극이므로 **재생·미리보기하지 않고** IRIS에만 입력한다.

### 5.1 확인 시험 결과 (2026-11-05, 집 GPU PC)

조건: IRIS `d96978ac1107` (2025-01-14), 기본 `appsettings.json` SHA-256 `ee78e54cb17c…`, `IrisApp -j 1 -p 1`, 24fps·6초, FFV1/MKV. 실행: `scripts/iris_selftest.py`.

| # | 자극 | 기대 | IRIS 결과 | 일치 |
|---|---|---|---|---|
| 1 | 흰↔검 4 Hz | 휘도 3 | 휘도 3 | ✅ |
| 2 | 흰↔검 1 Hz | 통과 | 통과 | ✅ |
| 3 | 흰↔검 2.5 Hz | 휘도 2 | 휘도 2 (연장 실패) | ✅ |
| 4a | 정지 세로 줄무늬 128×96, 주기 8px | 패턴 1 | **통과** | ❌ |
| 4b | 정지 세로 줄무늬 640×480, 주기 16px | 패턴 1 | **통과** | ❌ |
| 5 | 순적↔검 4 Hz | 적색 3 | 적색 3 **+ 휘도 3** | ✅ (적색 단독 아님) |
| 6 | 화면 10%만 4 Hz | 통과 | 통과 | ✅ |
| 7 | 1번을 손실 MP4(mp4v)로 | 1번과 동일 | 휘도 3, 동일 | ✅ |

**휘도·적색·면적 판정은 기대대로 동작한다.** 순적 깜빡임은 상대 휘도 변화(0→0.2126)도 기준(0.1)을 넘어 휘도 실패가 함께 붙는다. 따라서 합성 유형 `red`의 정답을 "적색 실패만"으로 가정하면 안 된다(4절 `type` 필드 항목과 일치). 7번은 전면 고대비 깜빡임 한 사례에서만 같았으므로, 경계 세기 자극에서는 무손실 저장을 유지한다.

**패턴 판정은 해상도가 아니라 줄무늬 주기가 픽셀 격자와 맞는지에 좌우되어 불안정하다.**

- IRIS 자체 양성 시험 이미지 `20stripes.png`(1920×1080)는 1920부터 128×96까지 모든 축소 해상도에서 패턴 실패로 판정되었다. 따라서 4번의 원인은 해상도가 아니다.
- 흑백 정지 줄무늬의 쌍 수(4~24쌍)를 640×360과 128×96에서 바꿔 보면 결과가 단조롭지 않다. 640폭 세로 줄무늬는 12·14쌍 실패, 16·20쌍 통과, 24쌍 다시 실패였다. 4쌍(8줄 ≥ `MinStripes` 6)은 어느 해상도에서도 감지되지 않았다.
- **위상 민감도:** 640×360에서 주기 40px 줄무늬를 1/8주기(5px)씩 옮기면 판정이 `0,1,0,1,0,1,0,1`로 번갈아 바뀐다. 주기 41px은 8개 위상 모두 실패, 128×96에서 주기 8px은 모두 통과, 10px은 모두 실패였다. 같은 패턴이 몇 픽셀 이동만으로 판정이 뒤집힌다.
- 추정 원인(미검증): IRIS는 DFT 전력 스펙트럼의 피크를 지운 역변환과 원본의 차이로 패턴 영역을 찾는다(`PatternDetection::hasPattern`). 주기가 DFT 크기를 정확히 나누는 등 에너지가 특정 빈에 몰리는 조건에서 이 차이 영상이 달라지는 것으로 보인다.

**결정:** IRIS 패턴 결과는 현 단계에서 **학습 정답으로 쓰지 않는다.** 기록(`pattern_max`, `fail_frames.pattern`)은 남기되 휘도·적색 판정과 분리해 보고한다. 합성 패턴 클립은 같은 클립을 1~2px 평행 이동한 사본으로 IRIS를 반복 실행하고, 판정이 일치하는 것만 "패턴 판정 안정"으로 표시하는 방안을 다음 단계로 둔다. ITU-R BT.1702의 패턴 기준과 대조할 별도 판정 근거도 필요하다.

## 6. 학습 창 라벨 규칙 (결정 필요)

IRIS의 프레임 결과는 "그 프레임까지 직전 1초(연장은 5초)"를 본 값이다. 16프레임 창의 라벨을 어떻게 만들지 정해야 한다.

- 안 A: 창의 **마지막 프레임** IRIS 결과 (인과적, 실시간 탐지기와 같은 조건)
- 안 B: 창 안의 **최댓값** (보수적, 위험 놓침 감소)
- 안 C: 프레임별 결과를 그대로 시계열 라벨로 사용

## 7. 작업 순서

1. ✅ 집 GPU PC에서 IRIS 빌드(VS 2026 BuildTools + vcpkg, `-DBUILD_EXAMPLE_APP=ON`), 커밋 `d96978a` 고정 — 실행 파일 `IrisApp.exe`
2. ✅ 5절 확인 시험 실행, 결과 5.1절 (휘도·적색 정상, 패턴 불안정)
3. ✅ `build_dataset.py --iris-clips` (144프레임·3구간 파형·FFV1 무손실 저장, 왕복 바이트 일치 확인)
4. ✅ `src/lumi/iris_labeling.py`, `scripts/label_iris.py` (실패 시 `iris_error`)
5. 라벨 분포 확인(통과/경고/실패/연장 실패, 유형별) → 합성 파라미터 조정
6. 6절 창 라벨 규칙 결정 후 GAN 학습 데이터 로더 수정

## 8. 위험과 열린 질문

- IRIS 마지막 커밋이 2025-01이다. 유지보수 상태와 ITU-R BT.1702-3 대응 여부를 확인해야 한다.
- IRIS 라벨로 학습한 모델은 IRIS의 오류도 함께 배운다. 외부 시험셋 평가는 다른 판정 근거(공인 도구·전문가 검수)로 해야 한다.
- 휘도 계산의 표시 장치 가정(sRGB, 최대 밝기)이 IRIS와 LUMI 사이에 같은지 확인한다.
- 생성 영상 파일은 유해 자극을 포함할 수 있으므로 git에 올리지 않는다(`.gitignore`의 `*.mkv` 등).
