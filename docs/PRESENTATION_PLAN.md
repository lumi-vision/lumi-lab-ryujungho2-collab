# 경진대회 발표 설계 (30 분) — "복원 가설을 세우고, 검증하고, 반증하고, 다시 설계했다"

> 원칙: 한 장에 주장 하나. 모든 그림은 `docs/figures/correction/` 에서 다시 만들 수 있고, 모든 숫자는 깃허브 원자료로 추적된다.
> ⚠️ 발표 화면에 **깜빡이는 영상을 재생하지 않는다**(청중 안전). 실제 위험 영상은 정지 화면·저대비 썸네일·도식으로만.

## 1. 논리 구조 — 왜 이 순서가 아름다운가

이야기 모양은 **"질문 → 측정 가능하게 만들기 → 대담한 가설 → 엄격한 검증 → 현실의 반증 → 원인 규명 → 더 나은 설계"**.
심사위원이 가장 높이 사는 것은 결과의 크기가 아니라 **(1) 문제를 숫자로 정의한 능력, (2) 결과를 보기 전에 기준을 정한 정직함, (3) 실패에서 원인을 찾아 다음 설계로 잇는 능력**이다. 우리 자료는 셋 다 갖췄다.

세 번의 '반전'이 긴장을 만든다:
1. 30 epoch 에서는 구성 요소가 효과 없어 보였는데 60 epoch 에서 결론이 바뀜 → "학습량을 맞추지 않은 비교는 거짓말을 한다"
2. 합성 test 에서 감광보다 훨씬 좋았는데(LPIPS 0.41 vs 0.66) 실제 영상에서 사람 눈에는 부자연스러움 → "합성 정답의 함정"
3. 실패의 95 %가 한 라벨(패턴)이었고, 그 라벨은 안전한 바탕의 36 %에서도 나옴 → "판정기 자체를 먼저 고쳐야 한다"

## 3. 그림 사용 규칙
- **핵심 그림 1 장 = 그림 04**(안전 × 화질 산점도). 오른쪽 위가 이상적 — "H 는 위로 갔지만 오른쪽 끝(95 %)에는 못 닿았다" 한 문장으로 설명.
- 학습 곡선(01)은 "잘 학습됐다" 한 가지만 말하고 넘어간다(시간을 쓰지 않는다).
- 반전마다 그림 하나: ① 06, ② 07 + 육안 정지 화면, ③ 08 오른쪽.
- 색 규칙: 파랑 = 우리 모델, 주황 = 팀원 감광 B2, 빨강 = 패턴/실패 강조. 모든 그림에서 같다.
